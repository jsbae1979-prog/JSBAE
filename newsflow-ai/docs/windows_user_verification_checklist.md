# Windows 11 사용자 검증 체크리스트 (Phase 5C.1)

## 머리말

- 이 체크리스트는 **사용자의 Windows 11 PC에서만** 수행합니다. Cloud(Linux)나 GitHub Actions 성공은 어떤 항목의 PASS도 대신하지 않습니다.
- 판정 어휘는 다섯 가지뿐입니다. **PASS** = 직접 확인했고 기대와 같음 · **FAIL** = 직접 확인했고 기대와 다름(앱 결함 의심) · **SKIPPED** = 의도적으로 수행하지 않음(예: 승인하지 않은 유료 호출) · **NOT VERIFIED** = 아직 확인하지 않았거나 이 환경에서 확인할 수 없음 · **BLOCKED** = 앱의 보수적 정책(robots·policy·OAuth 차단 등)이 의도대로 막음. BLOCKED는 결함이 아니며 정책을 완화해 PASS로 바꾸지 않습니다.
- **모든 항목의 기본값은 NOT VERIFIED**입니다. §10 결과 요약 표는 확인한 항목만 바꿉니다.
- 증거(스크린샷·JSON·MP4·로그)에 **API 키, 토큰, `session.key`, `ai-key.dpapi`, 사용자 이름·전체 경로가 보이는 로그**를 넣지 마세요. 키는 어떤 경우에도 채팅·Git·보고서에 넣지 않습니다.
- 유료 외부 AI 호출은 **§4.6의 승인된 단일 호출 1회**뿐입니다. 승인하지 않으면 §4.6과 §9.1의 `ai_usage` 기대값은 0입니다.
- 조작 방법·화면 문구는 [일반 사용자 안내서](user_guide_realcontent.md)를 따릅니다. 한국어 음성의 항목별 청취 기준은 [한국어 음성 청취 확인표](korean_tts_listening_checklist.md)입니다.

## 11. 증거 제출 안내

- **파일 이름**: `phase5c1-<번호>-<짧은설명>.<확장자>` (예: `phase5c1-2.5-connection-test.png`, `phase5c1-7-real-45s.mp4`, `phase5c1-4.6-ai-live-check.json`). 번호는 이 문서의 항목 번호입니다.
- **MP4 + SHA256**: 30/45/60초 세 편의 MP4와 `Get-FileHash -Algorithm SHA256` 결과를 `phase5c1-7-sha256.txt`에 함께 적습니다. 파일을 올릴 수 없으면 SHA256·크기·길이만 기록합니다.
- **JSON 증거**: `feed-review.json`, `ai-live-check.json`, `listening-*.json`은 그대로 제출합니다(설계상 키·본문이 없지만 제출 전 한 번 더 확인).
- **가림(redaction)**: 스크린샷에서 사용자 이름이 든 경로, 키 입력란, 브라우저 프로필 정보는 가립니다. 로그는 키·토큰·전체 경로가 없는 줄만 발췌합니다.
- **보고서 대응**: 이 표의 판정은 [Phase 5C.1 운영 준비도 보고서](reports/phase5c1_operational_readiness_report.md) §6·§15의 NOT VERIFIED 행과 1:1로 대응시킵니다. 기록하지 않은 항목은 보고서에서도 NOT VERIFIED로 남습니다.
- 제출 전 자문: 이 증거를 공개 저장소에 올려도 되는가? 아니라면 올리지 않고 요약만 전달합니다.
