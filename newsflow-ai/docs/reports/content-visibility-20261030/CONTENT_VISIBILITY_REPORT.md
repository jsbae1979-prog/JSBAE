# 콘텐츠 표시 기준 및 중복 스토리 오류 안내 보정

사용자가 라이브러리 삭제 항목이 콘텐츠 제작·게시 스튜디오에 남는 문제를 지적했고, 게시 스튜디오는 생성 완료 콘텐츠만, 성과 화면은 실제 게시 완료 자료만 보여야 한다고 지정했다. 기존 삭제는 라이브러리 전용 WorkspaceRemoval 표시였고 다른 화면은 전체 workspace.projects를 사용했으므로 표시 기준이 서로 달랐다. 이 보고서는 기존 라이브러리 전용 표시 결정에 대한 후속 변경이다.

| 화면 | 표시 기준 |
| --- | --- |
| 라이브러리·콘텐츠 제작 목록 | 라이브러리 휴지 보관 항목 제외, 복원 시 재표시 |
| 게시 스튜디오 선택 목록 | 휴지 보관되지 않은 생성 완료 콘텐츠 중 미디어 확인 가능 항목 |
| 성과 콘텐츠 목록 | 실제 게시 성공 증거가 확인된 콘텐츠. 초안·미게시·실패·결과 불명·합성 게시를 게시 완료로 표시하지 않음 |
| 비용·사용량 및 기존 게시 이력 | 삭제·게시 여부로 원본 비용·요청·승인·게시 기록을 지우지 않음 |

라이브러리 삭제는 SNS 게시 취소가 아니다. 이미 게시된 콘텐츠의 과거 게시/성과 이력은 보존하며, 실제 청구액이 확인되지 않은 값을 청구액으로 표시하지 않는다. 원본 DB·프로젝트·미디어를 삭제하거나 마이그레이션하지 않는다. 화면 목록을 필터링하고 같은 Chrome 세션의 화면 이동 시 읽기 자료를 갱신한다. 삭제된 선택 항목이 다른 콘텐츠에 잘못 매핑되지 않도록 편집 상태를 정리한다.

스토리 오류는 생성 버튼 아래 한 곳에서만 표시한다. 하단 중복 상자를 제거하고 기존 ‘새 스토리 입력’ 동작은 동일 안내 영역에 유지한다. API 키·모델 접근 확인 규칙, 비용·승인·결과 불명 보호는 변경하지 않으며 연결 확인이나 유료 요청을 실행하지 않는다.

개발 검증은 합성 자료/Fake와 외부 통신 차단 브라우저만 사용했다. 이후 승인된 정상 Stop·Start로 운영에 반영했으며, 실제 Chrome 표시는 아래 별도 읽기 전용 점검으로 확인했다.


## 구현 및 검증

작업 브랜치는 `codex/newsflow-character-shorts-automation-20261030`이다. 운영 기준 코드는 `531958cd2e3a0c0f32eaec500b985f56f36c7120`이며, 기존 라이브러리 UI 사용자 확인 결과를 재사용한다.

- 생성 완료 판정: 뉴스/이미지 success, 캐릭터 completed 상태와 실제 로컬 미디어 확인을 함께 사용한다. 초안·장면 검토 중·실패·누락 파일은 게시 후보에서 제외한다.
- 성과 판정: 성공한 게시 작업과 해당 작업의 실제 원격 ID 영수증, 저장된 계정·플랫폼 일치를 사용한다. 합성 게시, 단순 승인, 결과 불명은 게시 성공으로 해석하지 않는다.
- 과거 게시 계정은 변경 가능한 현재 초안이 아니라 해당 성공 영수증을 기준으로 한다. 초안 계정 수정 때문에 과거 성과가 사라지지 않도록 보완했다.
- 내부 이력 조회와 공개 활성 목록을 분리했다. URL 쿼리로 숨김 항목을 다시 노출하는 옵션은 추가하지 않았다.
- 같은 React 세션에서 라이브러리 삭제/복원 후 콘텐츠 제작 화면을 다시 열면 최신 목록을 읽는다. 게시 선택이 사라지면 편집 상태를 비워 다른 콘텐츠에 이전 정보가 연결되지 않게 한다.

집중 검증: **11 PASS / 0 FAIL / 0 ERROR / 0 SKIP**. 신규 검사 9개와 영향 범위 기존 검사 2개이며 이전 41 PASS 등은 새 결과로 합산하지 않았다. Python 3.12, Windows 합성 DB 및 외부 통신을 차단한 브라우저로 확인했다. TypeScript 검사·React 빌드·diff 형식 검사도 통과했다.

브라우저 검사 중 성과 비용 칸을 찾는 정규식 선택자 오류 1건이 발생했다. 제품 코드를 변경하지 않고 테스트 선택자를 수정한 뒤 해당 1건만 재실행해 통과했다. 기존 빌드의 번들 크기/라이브러리 지시어 및 TestClient 경고는 남아 있으며 실패로 분류하지 않는다. 전체 회귀·실제 API·운영 Chrome 자동화를 반복하지 않았다.

## 운영 Chrome 읽기 전용 표시 확인

정상 연결된 Chrome 확장 기능을 통해 사용자가 보고 있는 실제 운영 탭을 에이전트가 읽기 전용으로 확인했다. 상태는 **ASSISTANT_READ_ONLY_GUI_VERIFIED**이며, 사용자 본인이 별도로 확인했다고 기록하지 않는다. 기존 집중 검사 11 PASS를 재사용했고 신규 시험은 실행하지 않았다.
