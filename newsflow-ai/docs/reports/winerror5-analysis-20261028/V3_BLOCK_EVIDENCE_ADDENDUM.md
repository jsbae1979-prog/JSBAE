# V3 실행 차단 증거 추가 및 WinError 5 연관성 검토

2026-10-28 (Asia/Seoul). 기준 보고 커밋 `ea48985e4312885b4d88c350666fad62f730527f`.

**갱신 결론:** V3 Lite의 실행 차단 사실을 **사용자가 직접 확인해 제공한 증거**로 반영한다. 이전의 포괄적인 “차단 주체 미확정”은 현재 상태를 표현하지 않는다. 다만 차단 원인의 세부 규칙과 **오탐 여부는 NOT VERIFIED**다. 기존 WinError 5와의 연관성은 강하게 뒷받침되지만, 원본 개별 기록이 없어 모든 거부 요청을 6건과 일대일 대응했다고 주장하지 않는다. 설치형 후보의 실행 인수는 계속 **BLOCKED**다.

## 1. 새 증거와 출처

| 항목 | 사용자 확인 내용 |
|---|---|
| 제품 | AhnLab V3 Lite |
| 실행 차단 기록 | 6건 |
| 진단명 | Program Execution Notification |
| 탐지 분류 | 행위 기반 진단 |
| 검사 방법 | 클라우드 평판 기반 진단 |
| 상태 코드 | 5014 (사용자 제공 원문 그대로) |
| 시간 | 2026-10-28 19:53~20:56, 분 단위. 사용자/클라이언트 맥락에 따라 한국시간으로 기록 |
| 대상 | 기존 WinError 5 발생 NewsFlowAI-Candidate.exe라고 사용자 확인 |

원본 스크린샷·내보내기 파일은 이번 메시지에 첨부되지 않았다. 6개 개별 시각, 전체 경로, V3 기록 내부 해시 및 처리 세부 필드도 전달되지 않았다. 사용자 확인 사실을 낮춰 “기록 없음”으로 남기지 않되, 직접 원본을 검증한 것으로 표시하지 않는다. 상태 코드 5014는 Windows 오류 5와 다른 값이며 공식 의미를 임의로 해석하지 않는다. “Notification”이라는 진단명 문자열만으로 차단을 추론한 것이 아니라 사용자의 **실행 차단 기록 확인**에 근거한다.

## 2. 시간·경로·SHA-256 대조

| 차원 | 기존 증거 | 새 기록과의 관계 / 한계 |
|---|---|---|
| 파일명 | NewsFlowAI-Candidate.exe | 일치 |
| 경로 | `%TEMP%/nfpu-20261028/w3/Local/Programs/NewsFlowAI-Private/slots/1.0.0/NewsFlowAI-Candidate.exe` | 사용자 설명상 동일 대상. V3 원문 전체 경로가 없어 문자열 완전 일치는 미검증 |
| 바이너리 SHA-256 | `f3e24a91e7585089f95ac2e69063b1afb8e8a1e020c2786293d8bc66e0e955c4` | 기존 로컬 측정값 재사용. V3 기록/분석 접수 파일의 SHA-256이 없어 양측 해시 일치는 미검증 |
| 자동 ApplicationName 재현 | 부모94496, WinError5, 자식 PID 없음 | 결과 JSON 저장 시각 20:39:25 KST가 알려준 차단 구간 안에 있음 |
| 명시 ApplicationName 비교 | 부모59416, 같은 오류5, 자식 PID 없음 | 결과 JSON 저장 시각 20:56:30 KST가 마지막 보고 분(20:56)과 겹침. 개별 이벤트 초 단위 값은 없음 |

위 시각은 기존 JSON 파일의 LastWriteTimeUtc를 +09:00으로 변환한 **결과 저장 시각**이다. 정확한 Windows 프로세스 생성 시각, V3 이벤트 시각 또는 새 재현 시각이 아니다. 원본 JSON에는 요청의 절대 시각이 없으므로 시간 동기화 오차와 저장 지연까지 해소한 인과 일치 검증은 불가능하다. 초 단위 원본 기록이 없는 상태에서 6개 시각이나 PID를 만들지 않았다. 기존 두 재현과 6개 차단을 단순히 같은 개수의 테스트로 합산하지 않는다.

**판단:** 파일명·사용자의 동일 대상 확인·분 단위 시간대·CreateProcess 단계의 접근 거부가 서로 부합한다. 따라서 V3를 실증거가 있는 차단 주체로 갱신하고, WinError 5의 유력한 설명으로 기록한다. 단일 바이너리의 정확한 전체 경로/해시와 6건 각각의 인과 대응, 다른 실행 정책의 동시 관여까지 확정한 것은 아니다.

## 3. 실행 차단과 오탐의 구분

- **실행 차단:** 사용자 확인 증거 확보. V3 Lite가 해당 EXE를 차단했다는 보고를 반영함.
- **WinError 5와의 연관성:** 강한 정황 일치. 개별 원본 기록·해시 대조는 미검증.
- **오탐 / 정상성:** 미확정. 내부 CI·설치·FFmpeg PASS는 악성 여부나 평판 판정을 검증하지 않는다.
- **서명 효과:** 현재 후보 NotSigned 유지. 서명만으로 차단 해제가 보장된다고 판단하지 않는다.
- **제품 인수:** 앱 실행 실패가 해결되거나 GUI 성공이 새로 검증된 것은 아니므로 BLOCKED 유지.

안랩은 오진 의심 파일을 신고센터로 접수해 분석받도록 안내하며, 비악성으로 확인된 경우 엔진의 진단 제외 처리가 가능하다고 설명한다. 이는 이번 파일의 비악성 확인이나 처리 보장이 아니다. [공식 오진 안내](https://ask.ahnlab.com/hc/ko/articles/900002412366)

## 4. 이번 작업 범위

문서와 비민감 증거 JSON만 갱신했다. EXE/설치/전체 앱/FFmpeg/검사 도구 재실행 0, 새 진단 재현 0, V3 설정·예외·ACL 변경 0, 외부 제출 0. 원본 증거 JSON은 수정하지 않았다. 제품 코드·샘플·설치 후보도 변경하지 않았다.

기존 CI45 PASS / 설치19 PASS / FFmpeg7 PASS 및 이전 현장3 PASS·2 FAIL·0 ERROR는 **이전 결과**로 유지한다. 이번 신규 실행 테스트는 0건이다. 기존 운영 상태를 재조회하거나 운영 DB·키·설정·미디어·백업에 접근하지 않았다. PR35/main 및 기존 로컬 `validation/`은 그대로 보존한다.

## 5. 남은 자료와 후속 조건

현재 빠진 자료는 개별 V3 기록 6건의 시각·전체 경로·처리 결과, 가능하면 해당 파일 해시, V3 제품/엔진 버전과 공식 분석 회신이다. 새 실행으로 확보할 항목이 아니다. 사용자가 보유한 기록의 마스킹 사본이나 안랩이 확인하는 접수 바이너리 해시로 보완할 수 있다.

외부 제출은 아직 승인·실행하지 않았다. [분석 요청 준비 문서](AHNLAB_ANALYSIS_REQUEST_PREPARATION.md)에 준비 자료, 공식 제출 경로, 미전송 요청문을 정리했다. 공식 회신에서 원인과 조치가 제시되면 그 범위 및 별도 재실행 승인을 확인한다. 이번에는 보고서 갱신으로 종료한다.
