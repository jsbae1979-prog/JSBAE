## 2. Chrome 원인과 재시작 필요성

`newsflow/distribution/local_access.py`의 LaunchSession은 앱 시작 때 bootstrap과 session을 생성한다. bootstrap은 **발급120초 이내 한 번만** 사용할 수 있고 소비 후 폐기된다. 브라우저 session cookie는12시간이다. `LocalAccess`에는 현재 실행 세션의 bootstrap을 재발급하거나 다른 브라우저를 추가 등록하는 endpoint가 없다.

`app/controller/bat_distribution/windows_live.py`도 앱 시작 시 LaunchSession을 한 번 만들고 URL을 기본 브라우저에 전달한다. `/__bat/`는 소유 세션 정상 종료만 제공하며 인증 재발급 기능이 아니다. `launch_url()`을 다시 호출하는 것도 새로운 토큰 발급이 아니다.

직전 확인에서 Edge는 정상 인증됐고 Chrome은 정식 React 경로 `/studio/dashboard`에서 인증을 요구했다. Edge 쿠키·세션 복사나 소비된 토큰 재사용으로 해결하지 않는다. 파일의 브라우저 설정만 변경해도 이미 실행 중인 앱에 새 인증이 발급되지 않는다.

이번에는 같은 차단 화면을 다시 탐색하거나 토큰을 시험하지 않았다. **세 제작실·모델 선택·비용 화면의 이번 Chrome GUI 검증은 미실행/미검증**이다. 기존 TOP3 분석#42와 저장 프로젝트의 존재 확인은 직전 증거를 재사용한다.

## 3. 다음 승인 시의 정확한 정상 인증 절차

아래는 **미실행 계획**이며 운영 재시작 승인이 필요하다.

1. 현재 운영 PID·프로필·18768과 전환 전 복구 자료를 확인한다. 기존 승인 백업 절차로 DB·설정 복구 가능성을 확보하고 launch.json/layout.json의 원본 bytes·SHA를 보존한다. 원본169와 백업A/B는 변경하지 않는다.
2. 신규 설치본의 Stop BAT로 **해당 소유 세션만 정상 종료**한다. 종료0과 포트 해제를 확인한다. 실패·결과 불명이라면 강제 종료나 자동 재시도를 하지 않는다.
3. 기본 Edge가 새 인증을 먼저 소비하지 않도록, 기존 설정의 `openBrowser=false`와 그 layout hash binding만 일시 적용한다. 인증/CSRF/Origin·DPAPI·외부 실행 정책은 그대로다. 새 인증 endpoint를 추가하지 않는다.
4. Start BAT를 같은 프로필·같은18768로 실행한다. **새 PID가 생성되므로 기존 PID 유지는 불가능**하다. 새로 발급된, 아직 사용하지 않은 일회용 인증 URL을 정상 Chrome으로 전달해120초 안에 한 번 인증한다. URL fragment·토큰·쿠키는 출력/로그/보고서에 남기지 않는다.
5. 인증 후 React 홈·세 제작실·분석#42·프로젝트·비용 승인 화면을 확인한다. 생성 버튼이나 계정 확인 버튼은 승인된 범위를 넘겨 누르지 않는다. 자동화는 비활성으로 유지한다.
6. 검증 후 자동 열기 설정을 원래 값과 hash binding으로 복원한다. 이것은 새 브라우저를 즉시 열거나 현재 세션을 재발급하지 않는다. 실패 시 설정 백업으로 복원하고 결과 불명 상태에서 자동 재시작하지 않는다.

**영향:** 작업 중 잠시18768 접속이 중단되고 기존 Edge/Chrome 앱 인증은 새 세션으로 교체된다. 기존 탭은 재인증이 필요할 수 있다. DB 이전·migration·파일 삭제·유료 생성은 필요하지 않다. Windows 기본 브라우저 설정도 변경하지 않는다.

이 절차는 한 번의 Chrome 인수 동선이다. 현재 실행기는 OS 기본 브라우저를 여는 구조이므로 **향후 매번 자동으로 Chrome을 열려면 앱의 브라우저 선택 지원에 대한 별도 최소 보완이 필요**하다. 단순 재시작만으로 Chrome에 자동 인증된다고 약속하지 않는다.

## 4. API 등록과 사용자 직접 입력 절차

직전 승인 관찰을 재사용한다. Claude·ElevenLabs·Higgsfield의 참조 암호문은 있고 OpenAI의 `ai-key.dpapi`는 없었다. Claude는 Sonnet4.6 선택·과거 확인 기록, ElevenLabs는 Multilingualv2·음성 선택값이 있다. 현재 계정 권한을 다시 확인한 것은 아니다.

OpenAI가 참조하는 경로는 실제 현재 Windows 사용자 홈 아래 `AppData/Local/NewsFlowAI-BAT/v1/ai-key.dpapi`다. 키는 사용자가 정상 인증된 GUI의 **설정·관리 → AI 모델·API 키 → OpenAI 키 설정**에서 직접 입력해야 한다. 기존 `/api-settings/openai/key` 저장 경로와 CurrentUser DPAPI를 사용하며 채팅·Git·일반 설정파일에 키 원문을 전달하지 않는다. 저장과 실제 모델 접근 성공은 별개다.

**현재 준비 한계:** 운영 요청 경계는 `/api-settings/openai/key`와 공급사 확인 경로를 허용하지 않고, 프로세스의 native DPAPI 생성도 차단한다. 따라서 현재 GUI에서 키를 실제 저장할 수 있다고 표시하지 않는다. Chrome 인증과 별도로, 기존 DPAPI 저장·허용된 계정 조회를 정상적으로 연결하는 최소 운영 경계 보완 승인이 필요하다. 이번에는 allowlist·DPAPI·외부 실행 차단을 변경하지 않았다.

- **뉴스 쇼츠:** 저장된 TOP3 분석#42 재사용 대상과 수동 rank 선택 코드는 확인돼 있다. 자동화 TOP1은 요청대로 **PARTIAL 유지**. Claude 대본·ElevenLabs 음성·FFmpeg 연결은 기존 구현/증거를 재사용하며 이번 Chrome 동작은 미검증이다.
- **이미지:** 독립 프롬프트·모델·기본값과 TOP3의 독립 결과3건/부분 실패/unknown 보존 경로가 있다. 이번 모델 저장·생성 실행은 하지 않았다. OpenAI 키 등록·권한 준비가 남아 있다.
- **캐릭터:** 사용자가 이번에 명시한 **3~5장면**을 현재 지원 범위로 유지한다. 기존 참조 PNG→Claude→Seedance→FFmpeg→저장·미리보기 계약을 바꾸지 않는다.3장면 고정으로 다시 제한하지 않았다. 현재 Chrome 결과는 미검증이다.

## 8. 보존·최종 상태

이번에는 운영 파일/DB/키/미디어/백업에 쓰지 않았고 프로세스 제어·브라우저 인증 시도·실제 공급사 요청도 하지 않았다. 기존47개 테이블·169건·원본/A/B 보존7 PASS 증거를 재사용했으며 새 hash/실행 시험을 반복하지 않았다. 현재 생존 상태나 새 GUI 성공을 다시 측정했다고 주장하지 않는다.

키 원문·쿠키·토큰·DPAPI 평문을 수집/출력하지 않았다. 자동화 비활성,외부 실행 차단,무서명 업데이트 차단을 유지했다. V3 변경,main/PR35 변경·병합,외부 사용자 배포0이다. Git 변경은 이 보고서와 비민감 집계뿐이다.

**다음에 필요한 승인은 정상 Chrome 인증을 위한 제한된 운영 재시작·브라우저 동선과, 별도로 기존 키 저장/계정 조회 연결 범위다. 유료5건은 그 준비 이후 공급사별 비용 조건을 확인해 다시 승인해야 한다.** 이번 작업에서는 어느 승인도 대신 실행하지 않고 보고 후 중단한다.
