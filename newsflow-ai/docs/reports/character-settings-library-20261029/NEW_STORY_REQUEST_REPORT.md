# 새 캐릭터 작업이 이전 오류에 묶이는 UI 수정

2026-10-29. 사용자 캡처에서 새 캐릭터·주제를 선택했는데 이전 오류와 ‘작업 이력 확인 후 새 작업’ 안내 때문에 스토리 버튼을 누르지 못하는 상태를 확인했다.

## 원인과 변경

- 기존 코드는 오류 문자열이 하나라도 남으면 생성 버튼 전체를 비활성화했다. 실패 후 주제를 바꿔도 이전 요청 ID를 유지하여, 바뀐 본문을 같은 ID로 보내면 서버의 body-hash 불일치 검증에서 422가 발생할 수 있었다. 작업 이력의 존재 자체가 금지 조건인 것은 아니었다.
- 오류 전체를 이유로 버튼을 잠그는 조건을 제거했다. 주제·참조·설정·한도에 따른 명시적 새 입력은 새 요청 ID로 구분한다. 이미 결과 불명인 동일 입력은 자동 재전송하지 않는다.
- 초안 생성 전에 확정된 로컬 422 검증 오류는 유료 실행 결과 불명과 구분한다. 입력 수정 후 재입력할 수 있다. 참조 우선순위는 실제 전송 내용과 일치시켰고, 목록 갱신 실패로 busy가 계속 남는 문제도 정리했다.
- ‘작업 이력 확인 후 새 작업’을 강제하는 안내는 ‘새 스토리 입력’으로 바꿨다. 이전 작업·이미지·비용·결과 불명 이력은 삭제하지 않는다.

## 집중 검증 및 범위

실제 React 컴포넌트 함수와 disabled 조건을 Node에서 실행하고 외부 전송을 로컬 stub으로 대체한 집중 검사 8 PASS, TypeScript PASS, 최종 Vite 빌드 PASS다. 실제 Chrome에서 유료 생성 버튼을 눌러 Claude 성공을 확인한 결과가 아니다. API 권한·키 복호화·과금 한도를 추가로 확대하지 않았다.

‘자막·추가 음성 없는 FFmpeg 합성’ 수정 14 PASS와 함께 개발 브랜치에 보존했다. 두 변경은 아직 운영에 적용하지 않았고 추가 Stop·Start도 하지 않았다. 현재 사용자가 입력한 운영 화면·파일·DB·키·미디어는 이 개발 작업으로 변경하지 않았다.

최종 판정: CONDITIONAL — 개발·집중 검증 완료. 합성 Python 변경을 포함한 운영 적용에는 추가 정상 Stop·Start 승인이 필요하다. 실제 새 스토리/영상의 유료 생성은 이번 검증에서 실행하지 않는다.
