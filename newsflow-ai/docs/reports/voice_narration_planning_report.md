# 선택 음성·모델별 대본 분량 안내

기준 HEAD `0a313ce9d57c4ca2bce30a9662f8b3d784393a6e`, 기존 브랜치 `codex/newsflow-ux-video-app`와 Draft PR #35에서 작업했다. 운영 코드·앱·DB·키·음성·영상·설정·과거 실행 기록을 변경/재시작하지 않았다. 이번 작업의 실제 제작용 AI·음성/영상 공급사 API·계정 조회·OAuth·업로드·게시는 **0회**다. GitHub push와 변경 범위 CI는 별도로 수행한다.

## 문제와 변경

기존 Sola 결과는 공통 추정 28.2초, 실제 음성 24.055917초였다. 공통 추정은 Windows SAPI의 음절·문장 쉼 기준이므로 ElevenLabs의 특정 음성·모델이 같은 시간에 읽는다는 보장이 없었다. 실제 WAV 검사와 90% 최소 분량 차단은 정상 동작했고, 그 보호는 수정하지 않는다.

- 신규 V2 대본의 분량 안내에 선택 음성·모델을 연결했다. 동일 음성 ID·모델·속도·쉼 설정·저장 키 식별에 맞는 완료 WAV와 공급사 보고 사용량이 있어야 보정 안내를 만든다. 최소 3개의 서로 다른 입력, 합계 공통 추정 12초 이상이 필요하며 최근 최대 12개를 사용한다. 보정 범위도 제한한다. 이는 작성 안내이며 새 대본 길이·음질·사실성 보장이 아니다.
- 성공 응답·타임스탬프·WAV 검증 뒤에만 선택적으로 로컬 측정 근거를 추가한다. 완료 상태, 입력문·해시, WAV·해시·신호·실측 길이, 보고 사용량과 설정을 대조한다. 입력문은 동일 텍스트 연결을 확인하기 위한 기존 로컬 음성 캐시의 선택적 메타데이터이며 로그나 Git·공급사에 보내지 않는다. 비밀값이 든 음성 요청은 사전에 차단한다.
- 기존 캐시·결과 불명·실패·사용량 기록은 소급 수정하지 않는다. 명시적인 `remember_completed_cache` 경로는 이미 완료된 정확한 텍스트·음성·모델·키의 캐시만 확인해 별도 `narration-measurements.json`에 근거를 추가한다. 원래 ledger·WAV는 그대로이며, 캐시 부재·손상·결과 불명·보고 사용량 부재 시 호출로 대체하지 않는다. 이 경로는 자동 마이그레이션이나 새 메뉴가 아니다.
- 공통 한국어 발화 추정식과 사용자 음성 속도는 유지했다. 근거가 있는 새 작업에만 보정된 글자·발화 단위 안내를 전달한다. 장면 끝 여유와 프레임 반올림을 고려해 전체 작성 상한을 잡는다. 실제 30초 출력에 필요한 최소 음성 분량·장면 끝 여백·최종 WAV 검사는 계속 기존 렌더러가 판단한다. 무음 추가·절단·가속·자동 재생성을 하지 않는다.
- GUI 서비스·Autopilot·대본 저장/편집·작업 상세의 분량 안내와 제작 전 검사를 연결했다. 대본마다 사용한 측정 근거를 고정한다. 추가로 좋은 측정이 생겨도 과거 작업의 안내를 몰래 바꾸지 않으며, 근거·키·속도·WAV가 사라지거나 달라지면 경고하고 제작 전 확인을 요구한다. 보정 안내가 고정된 대본은 현재 전역 음성 선택이 바뀌어도 그 근거를 바꾸지 않으며, 실제 제작 음성·모델이 다르면 재검토를 요구한다. 기존 Autopilot의 작업별 선택 고정도 유지한다.
- 음성 ID·로컬 측정 근거·캐시 식별은 로컬에 보존하고 OpenAI/Claude에는 필요한 장면별 분량 숫자만 전달한다. 요청량 산정도 같은 전송 문자열을 사용한다. 저장 분석을 재사용하는 단일 대본 승인도 동일 음성 안내를 승인 지문에 묶어 1회 범위를 유지한다.
- 근거가 없으면 공통 추정이라는 안내와 실제 WAV 검사 필요를 표시한다. 다른 음성의 비율을 대신 쓰거나 새 측정을 얻으려고 호출하지 않는다. V1과 이전 대본에는 보정을 소급 적용하지 않는다. 별도 FFmpeg 숏폼 속도 효과가 켜진 경우 그 효과를 인증하는 실측으로 취급하지 않고 기존 계획·검사를 유지한다.
- Windows 확대 검증에서 로컬 `ledger.json` 교체의 간헐 `PermissionError / WinError 5`를 확인했다. 같은 잠금 안에서 같은 임시 파일의 원자적 교체만 최대 4번, 총 0.14초 대기 범위로 처리한다. 공급사 상태 조회나 생성 POST는 반복하지 않는다. 영구 저장 실패 시 기존 reserved 기록과 생성 캐시를 보존하고 동일 요청 재전송을 막는 것도 Fake로 확인했다. OS 권한·보안 설정을 변경하거나 기존 파일을 지우는 우회는 없다.

SQL migration, 새 메뉴/엔진, Provider 자동 전환, 비용 예약/한도 변경, 공개 게시 승인은 추가하지 않았다. 뉴스 출처·수치·날짜·인용·비밀정보·사람 검토·실제 음성 길이·결과 불명 재전송 방지를 유지한다. 기존 완료 캐시 재사용과 실패·결과 불명 요청 차단도 유지한다. 키는 계획을 읽을 때 복호화하지 않으며, 별도 캐시 경로에서도 키 파일을 복사할 필요가 없다.

## 검증

합성 키·DB·입력문·PCM WAV와 Fake HTTP만 사용했다. 외부 요청·자동 실행을 차단했다. 선택 음성별 안내가 API 요청·GUI 서비스·두 Provider의 Autopilot V2·수정 검토에 연결되는지, 다른 음성/모델/속도/키·손상된 WAV·사용량 누락·결과 불명·오래된 기록을 잘못 보정하지 않는지 확인했다. 기존 WAV의 명시적 재사용은 요청 0회와 원래 ledger 보존을 확인했다. 30/45/60초, 실제 음성의 과소/초과 차단, 단일 승인 재사용 차단, 현재 기본값 변경 시 기존 작업 보존을 검증했다.

확대 경계에서 두 기존 테스트의 오래된 기대값을 확인했다. V1 고정 기대 테스트는 수정 전 HEAD에서도 V2 기본값 때문에 같은 실패가 발생했고, 해당 모듈의 검증 대상을 명시적으로 V1에 고정했다. 새 음성 안내는 V2로 따로 검증한다. GUI 테스트의 예전 긴 안내 문구는 이미 적용된 `AI 초안 · 원문·출처 검토 필요` 문구에 맞췄으며, 기능·검토 절차와 화면은 바꾸지 않았다. 테스트 삭제·임의 skip은 없다. 기존 전체 회귀의 57 FAIL 이력도 보존하고 전체 회귀를 반복하지 않는다.

Windows 로컬 Python **3.14.7**: 최종 변경 범위 **461 PASS**, Ruff(`src tests tools`)·pip check PASS. 초기 개발 중의 중복 범위 결과는 합산하지 않는다. 간헐 Fake WAV 저장 오류는 앞서 설명한 Windows 파일 교체 거부까지 원인을 확인하고, 로컬 저장만 복구되는 경우와 영구 실패 후 요청 재전송이 막히는 경우를 별도로 검증했다. Fake 결과를 실제 Sola의 30초 분량 성공으로 표시하지 않는다.

Windows CI Python **3.12.10 / 3.14.8 각각 461 PASS**, Ruff·pip check PASS. 각각 warning 1건, 실패·skip 0이다. 구현 SHA `275e2e1a204036a94683e82a37e9c9baa66f89a1`을 [변경 범위 CI](https://github.com/jsbae1979-prog/JSBAE/actions/runs/39924785289)에서 검증했다. 3.12 job `120318393278`, 3.14 job `120318393087`. [비밀정보 없는 요약](evidence/voice-narration-planning/windows-ci.json). 최종 보고서 커밋은 런타임·테스트 코드를 바꾸지 않는다.

운영 DB/WAL·암호화 키 파일·이전 음성 일지/실행 기록과 기존 Sola WAV의 저장된 해시가 동일했다. 검증을 위해 운영 DB를 SQLite로 열거나 실제 키를 테스트에 넣지 않았다. 기존 MP4에는 접근하지 않았다. 비밀정보 없는 보존 요약은 로컬 `validation-output/voice-planning-preservation.json`에 보관한다.

## 남은 작업

운영 적용·재시작은 별도 승인 단계다. 기존 Sola 실측 파일과 사용량은 보호된 실행 폴더에 그대로 있고 이번 코드에 자동 반입하지 않았다. 운영 반영 전에 그 완료 캐시·텍스트·현재 키 식별을 대조해 로컬 보정 근거를 명시적으로 연결해야 한다. 이 연결은 API 호출 없이 가능하지만 이번 작업에서 실데이터로 실행하지 않았다.

그 다음 새 분량 안내를 검토한 대본과 음성의 실제 재검증이 필요하다. 새로운 유료 생성은 별도 승인 범위에서만 수행하며, 성공한 오디오는 재사용하고 실패·결과 불명 요청은 반복하지 않는다. 실제 한국어 음질·사람의 시청/청취·최종 30초 MP4·SNS 인증/게시는 계속 미검증이다. 이번 개발·Fake 검증 후 결과를 보고하고 추가 작업을 시작하지 않는다.
