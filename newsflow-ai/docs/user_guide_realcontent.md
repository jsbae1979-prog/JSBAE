# NewsFlow AI 일반 사용자 실행·설정 안내서 (Windows 11 · Phase 5C.1)

이 안내서는 NewsFlow AI를 **Windows 11 PC에서 처음 설치해 실제 뉴스 영상(30·45·60초)을 한 편 만들고 확인하는 사람**을 위한 문서입니다. 화면에 보이는 메뉴 이름·버튼·안내 문장은 Phase 5C.1 코드에서 그대로 옮겼습니다. 검증 판정은 **PASS / FAIL / SKIPPED / NOT VERIFIED / BLOCKED** 다섯 가지만 사용하며, 이 문서가 "된다"고 적은 항목도 사용자 PC에서 직접 확인하기 전까지는 NOT VERIFIED입니다.

범위: 설치와 실행 → 처음 설정하기 → 공개 RSS 등록 → (선택) 외부 AI → (선택) Windows 한국어 음성 → 영상 제작 → 대본·완성 영상 확인 → 게시 대기함 보관. 범위 밖: 실제 SNS 게시, 계정 로그인, 예약 실행, 한국어 발음의 자동 판정. 이 앱은 그 기능을 제공하지 않습니다([12. 이 앱이 하지 않는 일](#12-이-앱이-하지-않는-일)). 기술 설명은 [실제 콘텐츠 제작 설명](realcontent.md), 확인 결과 기록은 [Windows 11 사용자 검증 체크리스트](windows_user_verification_checklist.md)를 사용하세요.

## 1. 준비물과 설치

| 준비물 | 내용 |
|---|---|
| Windows 11 | 일반 사용자 계정이면 됩니다. **관리자 권한, WSL, Docker는 필요 없습니다.** |
| Python 3.12 또는 3.14 | [python.org Windows 다운로드](https://www.python.org/downloads/windows/)의 **Windows installer (64-bit)**. 설치 화면에서 **Add python.exe to PATH**를 반드시 선택합니다. 3.11·3.13은 지원 버전이 아니며 run.bat가 거부합니다. |
| FFmpeg · ffprobe | [FFmpeg 공식 다운로드 안내](https://ffmpeg.org/download.html#build-windows)에서 Windows 빌드를 받아 압축을 풉니다. `bin` 폴더 안에 `ffmpeg.exe`와 `ffprobe.exe`가 **모두** 있어야 합니다(libx264·AAC 포함 빌드). |
| 프로젝트 ZIP | 브랜치 ZIP을 **먼저 압축 해제**한 뒤 `newsflow-ai` 폴더를 사용합니다. ZIP 안에서 BAT를 직접 실행하지 마세요. 사용자가 쓰기 권한을 가진 폴더(한글·공백 경로 가능)에 두세요. |
| 인터넷 | 첫 실행의 Python 패키지 설치에만 필요합니다. 이후 체험 제작은 인터넷 없이 됩니다. |
| 한국어 글꼴 | Windows 기본 **맑은 고딕**(`C:\Windows\Fonts\malgun.ttf`)을 사용합니다. 없으면 `NEWSFLOW_FONT_PATH`로 사용 허가된 TTF/TTC/OTF 절대 경로를 지정합니다. |

### 1.1 FFmpeg를 사용자 Path에 넣기

1. 시작 메뉴에서 "환경 변수"를 검색해 **사용자 계정의 환경 변수 편집**을 엽니다.
2. 사용자 변수의 **Path → 편집 → 새로 만들기**에 압축 해제한 `bin` 폴더의 전체 경로를 넣습니다. 기존 항목은 지우지 않습니다.
3. 실행 중인 NewsFlow 창이 있으면 종료한 뒤 다시 실행합니다. 새 터미널에서 `ffmpeg -version`, `ffprobe -version`이 출력되면 준비된 것입니다.

Path를 바꾸고 싶지 않다면 PowerShell 세션에서 `$env:NEWSFLOW_FFMPEG`·`$env:NEWSFLOW_FFPROBE`에 절대 경로를 넣고 같은 창에서 `.\run.bat`를 실행할 수 있습니다. 앱은 FFmpeg를 자동 다운로드하지 않고 보안 검사를 끄지 않습니다.

### 1.2 setup.bat (준비 점검)

`newsflow-ai\setup.bat`를 더블클릭합니다. 가상환경 `.venv`를 만들고 패키지를 설치한 뒤 **영상 도구·한국어 글꼴·저장 폴더·여유 공간·한국어 음성**을 점검하고 결과를 한 줄씩 출력합니다. 콘솔에 나올 수 있는 영문 메시지는 다음과 같습니다(원문 그대로).

| 상황 | 콘솔 메시지 (영문 원문) | 뜻과 할 일 |
|---|---|---|
| Python 3.12 또는 3.14 없음 | `Python 3.12 또는 3.14 is required. Open START_HERE.html for the illustrated setup steps.` | START_HERE.html이 자동으로 열립니다. Python 3.12 또는 3.14를 설치하고 다시 실행합니다. |
| 폴더를 열 수 없음 | `Cannot open the project folder. Check its path and permissions.` | ZIP을 완전히 풀었는지, 폴더에 쓰기 권한이 있는지 확인합니다. |
| 점검 실패 또는 오류 | `NewsFlow AI did not start or stopped with an error. See README troubleshooting.` | 바로 위에 출력된 한국어 안내(항목별 `확인 필요`)를 해결하고 다시 실행합니다. 종료 코드 1. |
| 필수 항목 통과 | `Required preparation checks passed. Open run.bat to start.` | 종료 코드 0. 이제 run.bat를 실행합니다. |

점검 항목별 한국어 출력은 `항목 이름: pass · 준비되었습니다.` 또는 `항목 이름: needs_attention · 해결 방법` 형식이고, 마지막 줄은 `점검을 마쳤습니다. run.bat 실행 후 처음 설정하기를 열어 주세요.`입니다. 패키지 설치가 필요하면 먼저 `필요한 패키지를 설치합니다. 설치 완료 전에는 서버를 시작하지 않습니다.`가 표시됩니다. 점검을 끝내지 못하면 `준비 점검을 완료하지 못했습니다. 실행 중인 NewsFlow를 닫고 저장 폴더 권한을 확인하세요. 기존 데이터는 삭제하지 마세요.`가 출력됩니다. `한국어 Windows 음성 (선택)` 항목은 **선택 사항**이라 `확인 필요`여도 종료 코드는 0입니다. 어떤 경우에도 setup.bat는 프로그램을 자동 설치하거나 PATH·레지스트리·PowerShell 정책을 바꾸지 않습니다.

## 2. 실행과 종료

### 2.1 run.bat

`run.bat`를 더블클릭하고 **실행 창을 그대로 둡니다**. 정상 시작 시 콘솔에 다음 두 줄이 나옵니다.

```text
처음 실행하면 홈의 '처음 설정하기'에서 영상 도구와 한국어 음성을 점검하세요.
GUI 주소: http://127.0.0.1:8765 · 종료: Ctrl+C
```

브라우저(Chrome·Edge) 주소창에 **http://127.0.0.1:8765**를 직접 입력합니다. 주소는 127.0.0.1:8765 고정이며 외부 PC에서 접속할 수 없습니다. 포트를 바꾸려면 실행 전에 `$env:NEWSFLOW_PORT`를 설정합니다(자동 변경 없음).

| 상황 | 콘솔 메시지 | 할 일 |
|---|---|---|
| 같은 폴더에서 run.bat 중복 실행 | `이미 run.bat가 실행 중입니다. 기존 창을 먼저 종료하세요.` | 먼저 연 창을 찾아 그대로 쓰거나 Ctrl+C로 종료합니다. |
| 다른 프로그램이 8765 사용 | `포트가 사용 중입니다. 기존 서버를 종료하세요. 자동으로 다른 포트를 선택하지 않습니다.` | `netstat -ano \| findstr :8765`로 확인합니다. 모르는 프로세스를 함부로 끄지 마세요. |
| 잘못된 포트 설정 | `포트 설정은 1024~65535여야 합니다. 기본값은 8765입니다.` | `Remove-Item Env:NEWSFLOW_PORT` 후 재실행. |
| 예전 `data\newsflow.db` 발견 | `기존 data/newsflow.db가 있습니다. README의 migrate_data 명령으로 안전하게 이전한 후 다시 실행하세요.` | [README의 기존 Phase 1 데이터 이전](../README.md#기존-phase-1-데이터-이전) 절차를 따릅니다. |
| 종료 코드 1 | `NewsFlow AI did not start or stopped with an error. See README troubleshooting.` | 위에 출력된 한국어 원인을 확인합니다. 아무 키나 누르면 창이 닫힙니다. |

### 2.2 종료

실행 창에서 **Ctrl+C**를 누르고 `사용자가 프로그램을 종료했습니다.`가 나올 때까지 기다립니다. **브라우저 탭을 닫아도 프로그램은 종료되지 않습니다.** 창을 강제로 닫으면 진행 중이던 작업은 다음 실행에서 `중단됨`으로 표시되고 자동 재개되지 않습니다([11. 취소·재시도·재시작 보존](#11-취소재시도재시작-보존)).

## 3. 처음 설정하기 7단계

`/setup`의 7단계는 **1. 시작 안내 → 2. 뉴스 수집 방식 → 3. AI 기능 → 4. 영상 제작 → 5. 음성과 자막 → 6. 저장 위치 → 7. 완료와 테스트**입니다. 마지막 `설정 완료`를 누르기 전에는 기존 기본값을 덮어쓰지 않고, 중간에 닫아도 다음에 이어서 진행합니다. 다른 창에서 먼저 저장하면 `다른 창에서 설정이 바뀌었거나 이전 단계가 남았습니다. 새로고침해 주세요.`가 표시됩니다.

| 단계 | 화면 항목과 선택지 |
|---|---|
| 1. 시작 안내 | 설명만 있습니다. 아래 **준비 상태 점검**을 먼저 눌러 보세요. |
| 2. 뉴스 수집 방식 | `뉴스 가져오기`: **체험 뉴스로 연습 (추천)** / **내가 등록한 RSS 출처**. 등록 출처를 골라도 출처를 자동 등록·활성화하지 않습니다. |
| 3. AI 기능 | `대본 만들기`: **외부 API 없는 기본 대본 (추천)** 하나뿐입니다. 외부 AI(유료)는 [5. 대본 방식과 외부 AI (선택)](#5-대본-방식과-외부-ai-선택)의 `AI 연결 설정`에서만 켭니다. |
| 4. 영상 제작 | `기본 영상 길이` 30초/45초/60초 · `영상 목적지` **YouTube Shorts** / **Instagram Reels** (로컬 초안 구분용, 업로드 없음) |
| 5. 음성과 자막 | `음성` **무음 검토영상** 또는 설치된 한국어 음성(`이름 · 한국어`) · `발화 속도` 조금 느리게/약간 느리게/보통/약간 빠르게/조금 빠르게 · `문장 사이 쉼` 짧게/보통/여유 있게 · `자막 크기` 작게/기본/크게 · `자막 위치` **아래쪽 안전 영역** / 중앙 아래. 한국어 음성이 없으면 안내 문장이 표시되고 무음으로 진행할 수 있습니다. |
| 6. 저장 위치 | 뉴스·설정 폴더와 완성 영상 폴더를 보여 주고 `저장 위치를 확인했습니다` 체크가 필요합니다. 위치를 바꾸지 않습니다. |
| 7. 완료와 테스트 | 요약을 확인하고 `설정 완료` → `설정을 저장했어요` → `체험 영상 만들기`(체험 뉴스로 30초 무음/음성 영상, 외부 호출 없음). |

### 3.1 준비 상태 점검 (6개 항목)

같은 화면 아래의 `다시 점검하기`는 내 PC만 확인하며 외부 API를 호출하지 않습니다. 각 항목은 `준비됨` 또는 `확인 필요`로 표시됩니다.

| 항목 | 준비됨 조건 | 확인 필요 시 안내 |
|---|---|---|
| Python 실행 환경 | Python 3.12 또는 3.14 | `Python 3.12 또는 3.14를 설치한 뒤 run.bat를 다시 실행하세요.` |
| 영상 제작 도구 (FFmpeg · ffprobe) | 두 실행 파일 호출 성공 | `시작 안내의 FFmpeg 설치 방법을 따라 두 실행 파일을 PATH에 추가한 뒤 프로그램을 다시 실행하세요.` |
| 한국어 글꼴 | 한글이 실제로 그려지는 글꼴 | `Windows 언어 설정에서 한국어 글꼴을 설치하거나 고급 안내에 따라 글꼴 경로를 지정하세요.` |
| 저장 폴더와 데이터베이스 | 한글 파일 쓰기·DB 쓰기 가능 | `저장 폴더 쓰기 권한과 디스크 상태를 확인하세요. 기존 데이터는 삭제하지 마세요.` |
| 영상 제작 여유 공간 | 600MB 이상 | `저장 드라이브에 최소 600MB의 여유 공간을 확보하세요.` |
| 한국어 Windows 음성 (선택) | SAPI에 보이는 `ko-*` 음성 1개 이상 | 설치 안내 문장([6. 한국어 음성 (선택)](#6-한국어-음성-선택)) 또는 PowerShell 실행 정책 안내. **필수가 아니므로** 없어도 전체 판정은 준비됨일 수 있습니다. |

점검 결과 아래에는 `사람의 청취·시청 평가는 아직 하지 않았습니다.` 또는 `사람 청취 결과: PASS/FAIL/NOT VERIFIED (날짜, 청취자)`가 표시됩니다. 이 줄은 사람이 [청취 결과 기록](#65-청취-결과-기록)을 저장했을 때만 바뀝니다.

## 4. 뉴스 출처(RSS) 등록과 연결 테스트

사이드바 **뉴스**(`/sources`, 제목 "뉴스 출처와 모은 뉴스")에는 `1. 출처 · 등록한 RSS 출처`, `2. 수집 · 실제 뉴스 모으기`, `3. 뉴스 · 최근 모은 뉴스` 세 부분이 있습니다.

### 4.1 처음 보이는 출처

첫 실행 시 출처가 하나도 없으면 앱이 **`Google News · 한국`**(`https://news.google.com/rss?hl=ko&gl=KR&ceid=KR:ko`)을 **사용 안 함** 상태로 하나 넣어 둡니다. 이용 약관을 직접 확인하기 전에는 켜지 마세요. Phase 5C.1 Windows 실행(38718358049)에서 이 주소의 robots.txt는 `*` 그룹의 첫 일치 규칙이 `Disallow: /`라서 현행 robots 정책으로는 **BLOCKED(robots)**입니다. 켜도 수집되지 않으며 정책을 완화하지 않습니다. 같은 실행에서 수집이 확인된 출처(PASS)는 [공개 피드 검토](realcontent.md#공개-피드-검토-toolsci_feed_reviewpy) 결과를 참고하세요. Google News 항목의 원문 링크는 **중계 링크**일 수 있으며 앱은 링크를 바꾸지 않습니다.

### 4.2 등록 규칙

`새 출처 등록` 폼: `이름`(100자), `RSS 주소`(2048자), 체크박스 **"공개 RSS의 이용 약관·저작권을 확인했습니다."**, 버튼 `출처 등록`. 체크 없이 보내면 `공개 RSS 이용 약관·저작권 확인이 필요합니다.`로 거부됩니다.

- 허용: 공개 HTTP(S) 주소와 기본 포트. 거부: 사설·예약 주소, URL 안의 로그인 정보, 체험 뉴스 주소(`체험 뉴스 주소는 등록할 수 없습니다.`), 이미 등록한 주소(`이미 등록된 RSS URL입니다.`). 최대 100개.
- 새로 등록한 출처는 항상 **사용 안 함**으로 시작합니다. 켜려면 카드의 **`이용 권한 확인`** 체크 후 `사용하기`를 누릅니다(체크 없으면 `활성화 전 RSS 이용 권한을 확인해 주세요.`). 끄는 버튼은 `사용 안 함으로`입니다.
- `이름·주소 수정`에서 주소를 바꾸면 **사용 안 함으로 바뀌고 연결 테스트 결과가 지워집니다**. 새 주소의 약관 확인 체크가 다시 필요합니다.
- 기사 본문은 절대 가져오지 않습니다. 제목·요약·원문 링크·발행 시각만 저장합니다.

### 4.3 연결 테스트 절차

1. 카드의 `연결 테스트`를 누릅니다. 앱의 실제 수집 경로(공개 DNS 확인 → IP 고정 연결 → TLS 검증 → robots.txt → 리디렉션 3회 → 2 MiB·1000개 한도)로 피드를 **한 번만** 받아 파싱하고 기사는 저장하지 않습니다.
2. 성공하면 배지 `성공`과 결과 문장 **`기사 N개 · 발행시각 있음 N개 · 요약 충분 N개`**가 표시됩니다. "요약 충분"은 요약이 40자 이상인 기사 수입니다.
3. 실패하면 배지 `실패`, 원인 문장, `(유형: 종류)`가 표시됩니다. 유형별 의미와 할 일은 아래 표를 보세요.
4. `사용하기` → `지금 뉴스 모으기`를 누릅니다. 상단 칩이 `최근 수집 성공 · 신규 N`으로 바뀌고 카드의 `모은 기사 N개`가 늘어납니다.
5. **한 번 더** `지금 뉴스 모으기`를 누릅니다. 두 번째는 `신규 0`이 정상입니다(같은 기사는 중복으로 정리되며 중복 수는 DB 감사 기록에 `신규 0, 중복 N`으로 남습니다). 수집 중 다른 수집은 `이미 뉴스 수집이 실행 중입니다.`로 거부됩니다.
6. `최근 모은 뉴스`에서 기사를 열어(`/news/<번호>`) **발행시각 · 출처 · 원문 링크**가 피드와 일치하는지 봅니다. 기사 상세의 `내용 충분성`은 `요약 있음 · 원문 확인 필요` 또는 `요약 부족 · 제목 위주 초안만 가능`입니다.

수집 중 출처별 오류는 카드에 **`최근 수집 오류: [유형] 원인 문장`** 형식으로 남고 기존 기사는 지워지지 않습니다.

### 4.4 실패 유형 표

| 유형 | 화면 문장 (예) | 판정 | 사용자가 할 일 |
|---|---|---|---|
| `dns` | `RSS 호스트 DNS 조회에 실패했습니다.` | NOT VERIFIED | 주소 오타·인터넷 연결·회사 DNS 확인 후 재시도 |
| `https` | `RSS TLS 인증서 또는 HTTPS 연결 검증에 실패했습니다.` | NOT VERIFIED | 인증서 검사는 완화할 수 없습니다. 다른 공식 주소를 확인 |
| `timeout` | `RSS 요청 시간이 초과되었습니다.` | NOT VERIFIED | 고급 모드 Settings의 `외부 요청 타임아웃 · 초`(최대 30) 조정 후 재시도 |
| `http` | `RSS 서버가 HTTP 404을 반환했습니다.` | NOT VERIFIED | 발행사의 공식 RSS 안내 페이지에서 현재 주소 확인 |
| `robots` | `robots.txt 정책에서 이 RSS 경로를 허용하지 않습니다.` / `robots.txt 확인 실패로 수집을 중단했습니다.` / `robots.txt 요청 간격 정책을 지원하지 않아 수집을 중단했습니다.` / `crawl-delay가 지정된 출처는 Phase 1에서 수집하지 않습니다.` | **BLOCKED** | **정책에 따른 정상 차단입니다. 고치지 않으며 우회하지 않습니다.** 다른 출처를 쓰세요. robots.txt가 200·404 외로 응답해도 안전 쪽으로 차단합니다. |
| `parse` | `RSS XML 형식이 잘못되었거나 안전하지 않습니다.` / `RSS 또는 Atom 문서가 아닙니다.` / `RSS 문서를 정상적으로 파싱하지 못했습니다.` | NOT VERIFIED | 주소가 HTML 페이지가 아닌 RSS/Atom인지 확인 |
| `policy` | `RSS URL 형식이 올바르지 않습니다.` 등 주소 정책 위반 | **BLOCKED** | 사설 주소·비표준 포트·로그인 정보가 든 주소는 등록할 수 없습니다. 완화하지 않습니다. |
| `network` | `RSS 수집 또는 파싱에 실패했습니다.` (분류되지 않은 오류의 고정 문장) | NOT VERIFIED | 잠시 후 재시도. 원문 예외는 화면·로그에 넣지 않습니다. |
| `empty` | `피드에 기사 항목이 없습니다.` | NOT VERIFIED | 피드가 비어 있거나 항목 형식이 다릅니다. 발행사 안내 확인 |

`proxy` 유형은 코드에 이름만 있고 실제로 표시되지 않습니다. 앱은 robots.txt를 Python `urllib.robotparser`의 첫 일치 규칙으로 해석하며 User-agent 토큰은 `newsflowai`입니다. 발행시각은 RSS `pubDate`/Atom `published`에 시간대가 있을 때만 저장하고, 없으면 추정하지 않고 `미확인`으로 둡니다(날짜 필터에서 제외, 최신성 점수 미평가).

### 4.5 공개 피드 검토 도구와 후보 파일

`tools\feed_candidates.json`에는 후보 공개 피드 22개(17개 활성)가 들어 있습니다. 대부분의 후보는 `official_rss_page`가 `unknown`이고, URL이 적힌 4개(한겨레·NYT·Guardian·NPR)도 사람이 열어 확인하기 전까지 NOT VERIFIED입니다. 이용 약관은 모두 미확인이며 검토 결과 파일의 `terms_confirmed_by_human`은 `false`입니다. 앱을 종료한 뒤 프로젝트 폴더에서 다음을 실행하면 앱과 똑같은 경로로 각 후보를 검토하고 `feed-review.json`을 남깁니다(기사 본문·요약 미포함, 피드당 제목 최대 3개·80자).

```powershell
.\.venv\Scripts\python.exe tools\ci_feed_review.py --mode windows --output feed-review
```

판정은 PASS(연결 테스트 통과 후 수집 2회 연속 성공) / BLOCKED(robots·policy, 결함 아님) / NOT VERIFIED(dns·timeout·https·http·parse·빈 피드 등 이 환경에서 확인 못 함) / FAIL(앱 내부 결함만)입니다. Phase 5C.1 Windows 실행에서는 활성 후보 17개 중 PASS 12~13 · BLOCKED 3(Google News 2개 `Disallow: /`, Hacker News 대조군 `Disallow: /r`·crawl-delay 30) · NOT VERIFIED 1~2(GitHub 블로그 2 MiB 초과, UN 뉴스 압축 응답) · FAIL 0이었습니다. BLOCKED는 앱의 보수적 정책이 막은 정상 결과입니다. 조선일보·BBC 뉴스 등은 매 실행 PASS였습니다. 상세는 [공개 피드 검토](realcontent.md#공개-피드-검토-toolsci_feed_reviewpy)를 보세요.

## 5. 대본 방식과 외부 AI (선택)

기본값은 **기본 대본 (외부 호출 없음)**입니다. 기본 대본은 편집용 틀이며 외부 AI가 쓴 글이 아닙니다. 외부 AI 대본은 **실제 콘텐츠 제작에서만**, 그리고 **설정 → `AI 연결·API 키·사용량 →`**(`/ai-settings`, 제목 "AI 연결 설정")의 네 조건이 모두 맞을 때만 호출됩니다. **체험 제작은 어떤 설정에서도 외부 AI를 호출하지 않습니다**(요청하면 `ai_consent`로 거부).

### 5.1 네 가지 게이트 조건

| 조건 | 화면 항목 | 미충족 시 `외부 AI 사용 불가` 이유 문장 |
|---|---|---|
| 1 제공자 | `대본 제공자` = **OpenAI API (유료 · 승인 필요)** (`기본 대본 (외부 호출 없음)`이면 호출 없음) | `AI 제공자가 기본 대본(외부 호출 없음)입니다.` |
| 2 승인 | 체크박스 **"외부 AI 호출로 비용이 발생할 수 있음을 이해하고, 위 월 한도 안에서 실제 콘텐츠 제작에 사용하는 것을 승인합니다."** — 승인 날짜가 함께 저장되고, 해제하면 즉시 호출이 멈춥니다 | `유료 호출 승인이 저장되지 않았습니다.` |
| 3 월 토큰 한도 | `월 토큰 한도` > 0, 이번 달 사용량이 한도 미만 (승인 시 0이면 `외부 AI를 승인하려면 0보다 큰 월 토큰 한도를 함께 설정하세요.`) | `월 토큰 한도가 없습니다.` / `이번 달 토큰 한도를 모두 사용했습니다.` |
| 4 API 키 | `API 키` 섹션의 `새 API 키 입력` → `키 저장`(Windows 계정 보호 저장소 DPAPI, 파일 `ai-key.dpapi`) 또는 환경변수 `NEWSFLOW_AI_API_KEY`. 저장된 키가 우선. 화면에 다시 표시되지 않음 | `API 키가 없습니다.` |

게이트는 **대본 만들기 단계가 실제로 실행되는 순간** 다시 검사합니다. 저장된 키를 읽지 못하면 `ai_key_missing`, 제공자가 기본 대본으로 저장되어 있으면 `ai_consent`로 멈춥니다. 키는 DB·로그·화면·오류 메시지에 들어가지 않으며 키 문자열이 포함된 대본은 저장이 차단됩니다. `연결 상태 확인`의 `연결 확인하기`는 모델 정보를 조회할 뿐 토큰을 쓰지 않습니다. 고급 모드 AI Studio의 OpenAI Provider도 같은 승인·한도·키 규칙을 따릅니다.

### 5.2 예상 토큰·예상 비용 (표시용)

`지금 상태` 아래에 다음 형식의 문장이 보입니다.

> 실제 콘텐츠 1건(30초 기준) = 외부 AI 호출 2회 · 예상 최대 약 N 토큰 (입력 약 P + 출력 최대 O) · 이번 달 남은 R 토큰 · 예상 비용 C 또는 단가 미입력. 45·60초 대본은 출력 상한이 더 큽니다(1400·1800·2200 토큰). 실제 사용량은 호출 후 아래에 기록됩니다.

- 호출 2회 = 분석 1회(출력 상한 1600 토큰) + 대본 1회. 대본 출력 상한은 **30초 1400 · 45초 1800 · 60초 2200 토큰**입니다.
- 호출 전 예산 검사는 **`이번 달 사용량 + 이번 호출 예상 입력 + 출력 상한`**이 월 한도를 넘지 않을 때만 통과합니다(`ai_budget`).
- `단가 (선택 · 예상 비용 표시용)` 폼: `입력 토큰 100만 개당 단가`, `출력 토큰 100만 개당 단가`, `통화`(USD/KRW), 버튼 `단가 저장`. 폼 설명 원문: **"단가는 사용자가 입력한 값이며 공식 요금표를 확인하세요. 예상 비용은 참고용 추정치이고 실제 청구는 제공자 대시보드에서 확인합니다."** 비워 두면 `단가 미입력`으로 표시됩니다. 단가는 호출을 허용하거나 막지 않습니다.
- 상태 문장: **"예상 비용은 사용자가 입력한 단가로 계산한 참고값이며 이 앱은 요금을 보증하거나 결제하지 않습니다."**
- 같은 예상치는 `자동 제작` 시작 화면의 `대본 만들기` 아래(외부 AI 준비 완료 시), 단계별 제작의 `뉴스 고르기` 확인 화면(`이 뉴스로 외부 AI 대본을 만들면 호출 2회 · 예상 최대 약 N 토큰 …`), 작업 정보의 `외부 AI 예상`에도 나오고, 대본 생성 후에는 `실제 사용 N 토큰 (호출 2회 · 모델)`이 표시됩니다. `최근 요청별 사용량`에는 요청별 입력/출력/합계 토큰과 소요 시간이 남습니다.

### 5.3 승인된 단일 실제 호출 테스트 (사용자 PC 전용)

유료 호출 1회로 실제 OpenAI 연동을 확인하는 절차입니다. CI에서는 절대 실행되지 않으며, 사용자가 비용을 이해하고 승인한 경우에만 진행하세요.

전제: ① NewsFlow를 **종료**(Ctrl+C; 실행 중이면 `NewsFlow가 실행 중입니다. 프로그램을 종료(Ctrl+C)한 뒤 실행하세요.`로 BLOCKED) ② `/ai-settings`의 네 조건이 모두 충족 ③ 등록한 공개 RSS에서 **실제로 수집한 기사 번호**(`/news/<번호>`의 번호; 체험 뉴스는 `체험(합성) 뉴스는 외부로 보내지 않습니다.`로 BLOCKED).

```powershell
$env:NEWSFLOW_AI_LIVE_TEST = "1"
.\.venv\Scripts\python.exe tools\ai_live_check.py --article-id <번호> --max-tokens 1400 --output ai-live
Remove-Item Env:NEWSFLOW_AI_LIVE_TEST
```

도구는 `모델 … · 출력 상한 1400 토큰 · 예상 입력 약 P 토큰 · 예상 최대 N 토큰 · 이번 달 남은 R 토큰 · 예상 비용 …` 요약을 보여 준 뒤 **`동의`**를 입력하라고 묻습니다(다른 입력은 `사용자가 동의하지 않아 호출하지 않았습니다.`). 이미 승인한 경우 `--yes`로 생략할 수 있습니다. 분석은 오프라인으로 수행하고 **유료 호출은 정확히 1회**(대본 생성)만 합니다. 결과는 `ai-live\ai-live-check.json`에 저장되며 키·제공자 응답 본문·대본 본문은 들어가지 않습니다(대본은 SHA256과 글자 수만). 콘솔 마지막 줄은 `결과 PASS|FAIL|BLOCKED · 외부 호출 N회 · 증거 <경로>`입니다. 생성된 대본은 앱을 다시 켜면 고급 모드 AI Studio의 `저장된 초안`에서 확인할 수 있습니다.

**토큰 0 연결 확인**(대본 없음): 키를 환경변수로만 두고 다음을 실행합니다. 결과는 `연결 확인 PASS|FAIL|BLOCKED · 토큰 0 · 증거 <경로>`입니다.

```powershell
$env:NEWSFLOW_AI_LIVE_TEST = "1"
# 키를 명령줄에 직접 적지 마세요. PowerShell 기록 파일(ConsoleHost_history.txt)에 남습니다.
$newsflowKey = Read-Host 'OpenAI API 키' -AsSecureString
$env:NEWSFLOW_AI_API_KEY = [System.Net.NetworkCredential]::new('', $newsflowKey).Password
.\.venv\Scripts\python.exe tools\ai_live_check.py --connection-check --model gpt-4o-mini --output ai-live
Remove-Item Env:NEWSFLOW_AI_API_KEY; Remove-Item Env:NEWSFLOW_AI_LIVE_TEST
```

개발자용 opt-in 테스트 `tests\test_live_ai.py`(환경변수 `NEWSFLOW_AI_LIVE_TEST=1`, `NEWSFLOW_AI_API_KEY`, `NEWSFLOW_AI_LIVE_MAX_TOKENS`)도 유료 호출 1회를 하며 기본 테스트 실행에서는 건너뜁니다(SKIPPED).

### 5.4 AI 오류 코드와 해결 안내

| 코드 | 메시지 | 이렇게 해 보세요 |

## 6. 한국어 음성 (선택)

### 6.1 설치

> Windows 설정 → 시간 및 언어 → 언어 및 지역 → 한국어 → 언어 옵션에서 음성(텍스트 음성 변환)을 설치한 뒤 NewsFlow를 종료하고 run.bat를 다시 실행하세요.

설정 → 음성과 자막(`/voices`)과 처음 설정하기 5단계는 Windows **SAPI(System.Speech)에 보이는 `ko-*` 문화권 음성만** 목록에 올립니다. 고급 모드 Video Studio는 설치된 모든 SAPI 음성을 보여 주되 한국어가 아닌 음성에는 `(한국어 아님 · 한국어 대본 읽기 품질 미보장)`을 붙이고 기본 선택하지 않습니다. 어떤 경우에도 다른 언어 음성으로 몰래 대체하지 않으며 외부 유료 음성을 쓰지 않습니다. 음성이 없어도 **무음 검토영상**으로 모든 흐름을 진행할 수 있습니다. 특정 음성 이름(예: "Microsoft Heami Desktop")이 보이는지, Windows 11 24H2에서 음성 팩이 SAPI에 노출되는지는 **NOT VERIFIED**입니다.

### 6.2 상태 표시 (설정 → `한국어 음성·속도·미리 듣기 →`, `/voices`)

`지금 상태` 칩은 다음 중 하나입니다.

| 칩 | 뜻 | 할 일 |
|---|---|---|
| `한국어 음성 N개 설치됨` | SAPI에 한국어 음성이 보입니다 | 아래에서 선택·저장·미리 듣기 |
| `한국어 음성 0개 없음` | SAPI에 한국어 음성이 없습니다 | 설치 문장대로 설치 후 재실행. 그동안 무음 |
| `한국어 음성 0개 확인 불가` | SAPI 조회 자체가 실패(PowerShell 정책 또는 오류) | 아래 실행 정책 안내 확인. 무음으로 제작 가능 |
| `한국어 음성 N개 설치됨 · SAPI 미노출` | 레지스트리(읽기 전용)에는 한국어 **OneCore** 음성이 있지만 SAPI에는 보이지 않음 | 안내의 세 선택지 중 하나: ① 무음 유지 ② 음성 팩 재설치 후 재실행 ③ 사용자가 직접 레지스트리 복사(관리자 권한·비공식·자기 책임·백업 필수, 결과 UNCERTAIN). **앱은 레지스트리를 절대 수정하지 않습니다.** |

두 번째 칩 `현재 선택: 무음 검토영상` 또는 `현재 선택: <음성 이름>`(이 PC에 없으면 `· 이 PC에서 찾지 못함`), 세 번째 칩 `속도 … · 문장 쉼 …`, 그 아래 `사람 청취 결과: NOT VERIFIED · 자동 검증은 음성 파일이 생성되었는지만 확인합니다.`가 있습니다.

**PowerShell 실행 정책**: `PowerShell이 음성 스크립트 실행을 거부했어요.`가 보이면 PowerShell에서 `Get-ExecutionPolicy -List`로 현재 정책을 확인하세요. 사용자의 결정으로 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`를 적용할 수 있지만 **앱은 정책을 읽지도 바꾸지도 않습니다.** 바꾸지 않으려면 무음 검토영상으로 제작하세요.

### 6.3 선택과 저장

`기본 음성` 폼: `음성` = `무음 검토영상 (음성 없음)` 또는 `<이름> · <culture>`; `발화 속도` 느리게 / 조금 느리게 / 약간 느리게 / 보통 / 약간 빠르게 / 조금 빠르게 / 빠르게(-3~3); `문장 사이 쉼` 쉼 없음 / 짧게 (150ms) / 보통 (250ms) / 여유 있게 (400ms) / 길게 (600ms); 버튼 `음성 설정 저장` → `음성 설정을 저장했습니다. 다음 제작부터 적용됩니다.` 자막 크기·위치는 처음 설정하기 5단계에서 바꿉니다. 설치되지 않은 이름은 `사용 가능한 한국어 음성을 선택하거나 무음을 선택하세요.`로 거부됩니다.

### 6.4 미리 듣기와 읽기 형태

`미리 듣기`는 고정 문장만 합성합니다. 화면에 **원문**과 **읽기 형태 (음성에 전달되는 문장)**가 나란히 보이고 `읽기 형태 기준 예상 길이 약 N초`가 표시됩니다.

- 원문: `안녕하세요. 뉴스플로 음성 미리 듣기입니다. 2026-10-15 14:30 기준 KOSPI는 3.5% 올랐고, AI 기업 매출은 $1,250,000입니다.`
- 읽기 형태: `안녕하세요. 뉴스플로 음성 미리 듣기입니다. 2026년 10월 15일 14시 30분 기준 코스피는 3.5퍼센트 올랐고, 에이아이 기업 매출은 125만 달러입니다.` (날짜·시각·`KOSPI`·퍼센트·`AI`·달러 금액이 바뀜. 실제 화면의 문장이 기준입니다.)

`음성`·`속도`·`쉼`을 고르고 `미리 듣기 만들기`를 누르면 `voice-preview\preview-<id>.wav`가 만들어져 같은 화면에서 재생됩니다(이전 미리 듣기 파일은 삭제). 신호가 없는 WAV는 실패로 처리합니다. **읽기 형태 변환(날짜·시각·퍼센트·통화·단위·큰 수·범위·영문 약어)은 음성에 전달되는 문장에만 적용되고 자막·대본 원문·확인 사항은 그대로입니다. 한글은 바꾸지 않습니다.** 영상에서는 **장면 내레이션만** 읽고 도입(hook)·핵심 요약·마무리 문장은 읽지 않습니다. 발음·억양 품질은 사람이 들어야 하며 자동 검증은 "비무음 WAV 생성"만 확인합니다.

### 6.5 청취 결과 기록

같은 화면의 `청취 결과 기록` 폼은 **사람이 들은 결과만** 저장합니다. 항목: `청취자`(1~40자), `들은 음성`, `속도`, `쉼`, `항목별 판정`(명료도·음량·잡음·끝 잘림 / 숫자 / 날짜·시간 / 영문 / 문장 사이 쉼 / 속도 / 길이 / 자막 동기 — 각각 정확·부정확·불명), `종합 판정`(PASS / FAIL / NOT VERIFIED, 기본 NOT VERIFIED), `메모`(500자). 미리 듣기 직후 저장하면 그 WAV의 SHA256이 함께 기록됩니다. **PASS는 모든 항목이 정확일 때만 저장됩니다**(`PASS는 모든 항목이 정확일 때만 기록할 수 있습니다. 부정확·불명 항목이 있으면 FAIL 또는 NOT VERIFIED를 선택하세요.`). 청취자·음성 이름에는 가운뎃점(·)을 쓸 수 없습니다. 저장 결과는 `voice-listening\listening-<id>.json`(최근 50건 보관)과 설정 `voice_listening_last`에 남고, 화면에는 `사람 청취 결과: PASS (날짜, 청취자)`처럼 표시됩니다. 앱과 자동 테스트는 어떤 경우에도 PASS를 기록하지 않습니다. 항목별 기준은 [한국어 음성 청취 확인표](korean_tts_listening_checklist.md)를 따릅니다.

### 6.6 음성 관련 오류 코드

| 코드 | 메시지 | 이렇게 해 보세요 |
|---|---|---|
| `voice_unavailable` | 선택한 한국어 음성을 이 PC에서 찾지 못했습니다. 음성 설정을 확인하거나 무음으로 제작하세요. | 설정 → 음성과 자막에서 설치된 한국어 음성을 다시 선택하거나 무음 검토영상으로 제작하세요. |

오류 패널에는 `음성 설정 →`과 (대본이 있으면) `대본 수정 →` 링크가 함께 나옵니다. 한국어 음성으로 제작할 때 앱은 장면별 음성을 먼저 만들어 길이를 재고 각 장면에 **음성 길이 + 0.35초**를 보장한 뒤 남는 시간을 대본 비율로 나눕니다. 자막 구간도 같은 시간표를 씁니다.

## 7. 영상 만들기

### 7.1 시작 화면 (`자동 제작`, "어떻게 만들어 볼까요?")

| 항목 | 선택지 |
|---|---|
| 1. 뉴스 종류 | **체험 제작**(연습용 체험 뉴스, 외부 호출 없음, "처음이라면 추천") / **실제 콘텐츠 제작**(등록한 RSS에서 실제 뉴스, `등록 출처 N개 사용 중 · 뉴스 출처 관리`) |
| 2. 제작 방식 | **간편 제작**(이어서 제작, 실제 콘텐츠는 대본·완성 영상에서 멈춤) / **단계별 제작**(뉴스 선택·대본·영상을 하나씩 확인) |
| 3. 영상 길이 | 30초 / 45초 / 60초 |
| 영상의 목적지 | YouTube Shorts / Instagram Reels (로컬 초안 구분, 실제 게시 없음) |
| 대본 만들기 | **기본 대본 (외부 호출 없음)** / **외부 AI 대본 (OpenAI · 유료)** — 게이트가 닫혀 있으면 `· 준비 안 됨`으로 비활성 |
| 음성 | `기본 설정 사용 · <무음 검토영상 또는 음성 이름>` / `이번만 무음 검토영상` |

`선택한 방식으로 제작 시작 →`를 누르면 작업 화면(`/autopilot/jobs/<작업번호>`)으로 이동합니다. 사용 중인 출처가 없으면 `no_sources`(`사용 중인 뉴스 출처가 없어 제작을 시작하지 못했습니다.`)로 멈추고 `뉴스 출처 설정` 링크가 나옵니다.

### 7.2 실제 콘텐츠 흐름과 두 번의 필수 멈춤

여섯 단계는 **뉴스 모으기 → 뉴스 고르기 → 대본 만들기 → 영상 만들기 → 영상 확인하기 → 게시 대기함에 보관**입니다. 실제 콘텐츠 제작은 제작 방식과 관계없이 **`대본 만들기` 뒤와 `영상 확인하기`에서 반드시 멈추고**(상태 `내 확인 필요`) 사람이 버튼을 눌러야 다음으로 갑니다. 단계별 제작은 `뉴스 고르기`에서도 멈춥니다.

| 멈춤 | 화면 제목 | 버튼 |
|---|---|---|
| 뉴스 고르기 (단계별) | `이 뉴스로 만들어 볼까요?` — 후보 목록에서 라디오 선택, `뉴스 자세히 보기` 링크 | `선택한 뉴스로 대본 만들기 →` |
| 대본 (실제 콘텐츠 필수) | `대본을 읽고 원문과 비교한 뒤 진행해 주세요.` | `이 대본으로 영상 만들기 →` |
| 최종 영상 (실제 콘텐츠 필수) | `영상을 재생해 보고 대기함에 보관하세요.` + 최종 확인 3항목 | `게시 대기함에 보관하기 →` |

화면의 안내대로 "다음 단계로 넘어가도 게시 승인이나 저작권 확인으로 기록되지 않습니다."

### 7.3 진행 화면

- 제목: 진행 중 `이야기가 영상이 되고 있어요.` / 확인 대기 `잠깐, 결과를 확인해 주세요.` / 완료 `영상이 준비되었어요.` / 실패·중단 `잠시 멈췄어요. 함께 확인해요.` / 취소 `제작을 취소했습니다.`
- 상태 배지: `준비 중` · `제작 중` · `내 확인 필요` · `제작 완료` · `확인 필요`(실패) · `중단됨` · `취소됨`. `전체 진행률` 퍼센트와 여섯 단계 목록(`현재 단계`, 멈추는 단계에는 `· 내 확인 필요`)이 표시되고 약 1.5초 간격으로 새로고침됩니다.
- 오류 시 `이 단계에서 작업이 멈췄습니다.` → 메시지 → `이렇게 해 보세요` → 해결 안내 → 상황별 링크(`뉴스 출처 설정`, `AI 연결 설정 →`, `음성 설정 →`, `대본 수정 →`, `영상 제작 준비 다시 점검 →`) → 재시도 가능하면 `확인 후 다시 시도`.
- 오른쪽 `완성 영상` 패널: 플레이어, `무음 검토영상 · 음성 없음` 또는 `한국어 음성 포함 · 시청 품질은 직접 확인`, `MP4 저장`, `영상 수정`(Video Studio), `게시 대기함에서 확인 →`, `내 PC 저장 위치`. `작업 안내`의 `제작 취소`와 `작업 정보`(작업 번호·대본 종류·외부 AI 예상/실제·음성).

## 8. 대본 검토

`영상 대본` 패널 첫 줄은 `<대본 종류> · 버전 N · 사실 확인 미완료 · 예상 음성 길이 X초 / Y초 (맞음)` 또는 `(초과 · 대본을 줄이세요)`입니다. 예상 길이는 한국어 약 5음절/초와 문장 쉼을 기준으로 한 계획값이며 실제 WAV 길이 검사를 대신하지 않습니다.

### 8.1 확인 사항 메시지

서버가 저장 시 계산해 `대본 확인 사항` 목록으로 보여 줍니다. 대본을 고치지는 않습니다.

| 메시지 | 뜻 |
|---|---|
| `원문 제목·요약에 없는 숫자가 대본에 있습니다: …` | 대본의 숫자가 원문에 없습니다. 원문 링크를 열어 확인하고 없으면 지우세요. |
| `원문 RSS 요약이 짧거나 없습니다. 대본은 제목 위주의 초안이므로 원문 링크를 읽고 내용을 보완·확인하세요.` | 요약 40자 미만. 대본은 원문에 없는 내용을 추측해 채우지 않습니다. |
| `원문 발행 시각을 확인하지 못한 기사가 있습니다. 시점을 단정하는 표현이 없는지 확인하세요.` | 발행시각 미확인 기사. "오늘", "방금" 같은 표현에 주의. |
| `장면 N의 음성 예상 길이 X초가 배정 Y초를 넘습니다. 문장을 줄이거나 영상 길이를 늘리세요.` / `전체 음성 예상 길이 X초가 영상 길이 Y초를 넘습니다.` | 음성으로 제작하면 `speech_too_long`이 날 수 있습니다. |

문제가 없으면 `자동 점검에서 숫자·날짜·길이 문제를 찾지 못했어요. 그래도 원문과 직접 비교해 주세요.`가 표시됩니다.

### 8.2 원문과 비교하기

`원문과 비교하기`를 펼치면 **원문 제목 · RSS 요약(없으면 `요약 없음 · 원문 링크를 확인하세요`) · 출처 · 발행 시각 · `원문 열기 ↗`**가 보입니다. 제목·요약·출처·날짜가 대본의 내용과 다르지 않은지, 대본이 원문에 없는 주장을 더하지 않았는지 확인합니다.

### 8.3 대본 수정 → 버전 증가 → 영상 재제작

`대본 수정 →`는 고급 모드 AI Studio(`/ai?draft_id=…`)로 이동합니다. 수정 가능한 항목: `영상 제목`(100자), `후킹 문구`(200자), `핵심 요약`(500자), `마무리 문장`(200자), 장면별 `길이(초)` · `내레이션`(400자) · `자막`(150자) · `소재 제안`. 장면 길이 합계는 영상 길이와 같아야 합니다. `수정 초안 저장`을 누르면 **버전(revision)이 1 올라가고**, 이미 만든 영상은 바뀐 대본을 반영하지 않으므로 **영상을 다시 만들어야** 합니다. 대본과 영상의 버전이 맞지 않으면 게시 대기함 보관이 차단됩니다. 출처 목록(`원문 출처 · 변경 불가`)은 수정할 수 없습니다.

### 8.4 금지 사항

- 원문 제목·요약에 없는 사실·숫자·인용을 넣지 않습니다. 사실 확인은 사람이 원문에서 합니다.
- 대본 본문에 URL이나 API 키 같은 비밀 문자열을 넣지 않습니다(저장 차단).
- 체험 뉴스로 만든 대본·영상을 실제 보도처럼 다루지 않습니다(화면에 `체험 뉴스 · 실제 보도 아님` 표시).
- 확인 사항이 비어 있어도 검토 완료가 아닙니다. 모든 대본은 `검토 필요` 상태를 유지합니다.

## 9. 완성 영상 확인과 보관

### 9.1 카드 구성 (1080×1920, 장면마다)

| 위치 | 내용 |
|---|---|
| 상단 띠 | `NEWSFLOW · 미확인 보도 · 사람 검토 필요` |
| 제목 | 대본 제목, 56px, **최대 5줄**(넘치면 잘림) |
| 중앙 | 로컬 이미지(허가한 소재) 또는 기본 상자 `장면 NN` · `텍스트 기반 뉴스 브리핑` |
| 자막 | 장면 자막, 설정 크기(40/48/56px 또는 Video Studio 36/48/64px), **앱 한계 최대 4줄**. 넘으면 `자막이 안전 영역을 초과했습니다. 자막을 줄이거나 크기를 낮추세요.`로 제작 실패. 2줄 이내를 권장합니다. |
| 우하단 | `무음 검토영상 · 음성 없음` 또는 `한국어 음성 · 발음 품질 미검증` |
| 하단 | `출처: 발행사 · 도메인 / …` **최대 3개**, 2줄까지 |

### 9.2 최종 확인 (영상 확인하기 단계)

화면의 `최종 확인` 세 항목: ① 영상 속 내용이 원문 보도와 다르지 않은지 ② 무음이면 `무음 검토영상입니다. 음성은 들어 있지 않아요.`, 음성이면 `음성이 자막과 맞게 들리는지 (발음 품질은 직접 판단)` ③ 출처 표시와 사용한 소재의 권리. 앱의 자동 검사는 ffprobe로 MP4/H.264/AAC/1080×1920/길이 오차 0.25초 이하만 보고 SHA256으로 보관 전 변경을 감지합니다. 재생·자막 가독성·음성 품질은 사람이 판단합니다.

### 9.3 게시 대기함

`게시 대기함에 보관하기 →`를 누르면 `/queue`에 `검토 대기` 배지와 함께 카드가 생깁니다. 카드에는 플레이어, 제목·설명, `게시 전 확인 사항`(`○ 내용 확인 필요` · `○ 출처 확인 필요` · `○ 권리 확인 필요`; 세 가지 모두 처음엔 "필요"), `영상 파일 검증 완료 · 게시 승인 대기`, 버튼 `게시 초안 수정`(고급 Publishing)과 `영상 저장`이 있습니다. 상단 안내처럼 **"여기에 보관한 영상은 SNS에 전송되거나 게시되지 않습니다."** 고급 Publishing에서 세 체크박스(`영상·음성·자막·제목·설명을 사람이 검토했습니다.` / `영상·음성·소재의 사용 권한과 저작권을 확인했습니다.` / `원문 출처와 미확인 사실을 검토했습니다.`)를 저장하고 `게시 전 검증 실행`을 누르면 항목별 PASS/FAIL/NOT VERIFIED가 표시되지만, `사용자 최종 승인 대기`는 게시 가능 상태가 아니며 `실제 OAuth 연결 · 차단` 버튼은 항상 비활성입니다.

완성 파일은 `%LOCALAPPDATA%\NewsFlowAI\outputs\videos\video-<고유번호>.mp4`이며 기존 파일을 덮어쓰지 않습니다. 보관용 사본과 SHA256은 PowerShell `Get-FileHash <파일> -Algorithm SHA256`으로 남길 수 있습니다.

## 12. 이 앱이 하지 않는 일

- SNS(YouTube·Instagram 등)에 **게시·업로드하지 않습니다.** 게시 대기함은 내 PC의 로컬 초안입니다.
- **계정에 로그인하지 않고** OAuth 토큰을 발급·저장하지 않습니다(`/api/oauth/safety`는 `OFFLINE/BLOCKED`, `실제 OAuth 연결 · 차단`).
- **예약·주기 실행·무인 운영이 없습니다.** 모든 제작은 사람이 시작하고, 실제 콘텐츠는 두 번 멈춥니다.
- **한국어 발음·시청 품질을 자동 판정하지 않습니다.** 자동 검사는 WAV 생성과 MP4 규격뿐이며 청취 결과 PASS는 사람만 기록합니다.
- 기사 **본문을 수집·스크래핑하지 않고** 로그인·유료 벽을 우회하지 않습니다. 뉴스 이미지·영상을 내려받지 않습니다.
- **요금을 계산·보증·결제하지 않습니다.** 예상 비용은 사용자가 입력한 단가로 만든 참고값이고 호출 차단 기준은 월 토큰 한도뿐입니다.
- 체험 제작에서 **외부 AI를 호출하지 않습니다.** 외부 AI는 실제 콘텐츠 제작에서 네 조건이 맞을 때만 호출합니다.
- robots.txt·SSRF·TLS·리디렉션 정책을 **완화하지 않습니다.** BLOCKED는 결함이 아닙니다.
- PowerShell 실행 정책·레지스트리·PATH를 **바꾸지 않고**, 프로그램·글꼴·FFmpeg를 자동 설치하지 않습니다.
- 다른 언어 음성으로 **대체하지 않습니다.** 선택한 음성이 없으면 멈춥니다.
- 실제 콘텐츠 제작·자동 제작에서는 Higgsfield 등 외부 영상 생성 API를 **호출하지 않습니다.** Phase 5D의 선택 기능인 AI 고품질 제작은 사용자가 승인·한도·모델·키를 저장하고 장면을 직접 고른 경우에만 쓰입니다([AI 고품질 제작 안내](user_guide_ai_video.md)).
