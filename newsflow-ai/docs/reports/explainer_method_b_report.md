# 해석형 대본 방법 B — 구현·Fake 검증

## 범위와 판정

- 기준: `codex/newsflow-ux-video-app` / `bc8e0dc273beb46fd19cfa1873dfcd11c28c8022`, 기존 Draft [PR #35](https://github.com/jsbae1979-prog/JSBAE/pull/35).
- 개발·검증은 Windows의 `integration-final-20261022/candidate`에서 수행했다. 운영 프로젝트·LocalCache DB·DPAPI 키·설정·영상·기존 이력은 접근·변경하지 않았고 운영 앱은 재시작하지 않았다.
- 이번 결과는 구현과 합성 자료/Fake 응답 검증이다. 실제 OpenAI/Claude 호출, OAuth, 업로드·게시 0회. 실제 모델의 해석 품질·추천 결과·음질·토큰 비용 증가율은 **NOT VERIFIED**다.
- 문서의 완료 기준 중 실제 동일 자료 V1/V2 생성 비교와 실제 비용 검증은 남아 있다. Fake PASS를 실제 대본 개선 완료로 확대하지 않는다.

## 변경

1. 기존 V1 분석·대본 지시문 문자열을 그대로 보존하고 V2를 추가했다. 신규 API 작업 기본값은 `NEWSFLOW_SCRIPT_PROMPT_VERSION=v2`; `v1` 설정으로 신규 요청만 되돌릴 수 있다. CLI·기존 체험 경로는 기존 지시문을 유지한다.
2. V2는 질문/오해 훅 → 짧은 사실 → 시청자에게 중요한 의미 → 확인할 일로 구성한다. QUICK 3장면, STANDARD 4장면을 유지하고 후속 일정이 있는 경우에만 `next`를 요청한다. 투자·상품·구매 권유 대신 확인할 일을 제시한다. 고위험 소재에는 비선정적 실루엣·아이콘·텍스트를 요청한다.
3. 대본 `analysis`와 장면 `role`, 비교의 `viewer_relevance/ad_risk/viewer_angle`, 분석의 `recommended_angle`은 선택 필드다. 계획 문자열은 150자, 분석 관점은 300자로 정규화하고 잘못된 enum은 None으로 처리한다. 기존 필드의 필수 구조·길이·출처 검사는 유지한다. 새 필드가 없는 V1 JSON은 저장 형태도 유지한다.
4. 역할 순서·해석 시간·원문 이동형 마무리는 생성 거부 대신 안전한 로그와 검토 안내로 남긴다. 이 세 항목은 `composition_warning` 정보 항목이므로 문체 문제만으로 검토 생략을 하드 차단하지 않는다. 고위험 소재는 별도 검토 경고이며 자동 생성 금지는 아니다. 기존 분량·출처·위험·공개 게시 보호는 유지한다.
5. 해석·계획 필드에도 숫자·날짜·직접 인용·비밀정보 검사를 적용한다. 정규화로 잘리기 전 원본을 검사해 뒷부분에 숨은 내용을 놓치지 않는다. 분석 관점은 연결된 후보 자료에만 대조하며 점수·순위를 사실 수치로 오인하지 않는다. 이 검사는 자동 사실 검증이나 의미 검증의 완성을 뜻하지 않는다.
6. API 분석 결과의 추천 관점을 V2 대본 입력에 전달한다. 새 작업의 버전을 저장하고 Autopilot 분석·대본·결과 재사용에서 고정한다. 환경값이 바뀌어도 기존 작업·캐시를 새 버전으로 바꾸거나 API를 다시 요청하지 않는다. 기존 UI 편집은 누락된 계획·역할 메타데이터를 보존한다.
7. 음성·자막·영상은 기존 장면 내레이션만 사용한다. `analysis`와 `role`은 방송 문장에 덧붙이지 않는다. 별도 hook/closing을 다시 읽지 않고 첫/마지막 장면 내레이션에 한 번만 포함하도록 요청한다. 기존 음성 길이 추정식은 변경하지 않았다. 새 장면 구성의 내보내기도 중간 의미 장면을 빠뜨리지 않는다.
8. 기존 화제성 점수·전체 기사 그룹·top_k·출처 보호와 숏폼의 훅 시간·분량·구독 권유 금지를 유지한다. V2 일반 대본에는 과거 HOOK/CONTENT/ENDING 3장면 문자열 일치 규칙을 적용하지 않지만 기존 근거·분량 조건은 유지한다.

## 호출·토큰 기록

- V2 분석 출력 여유분 +400, 대본 +600. 기존 모델 상한을 넘지 않는다(Claude Sonnet 4.6의 기존 100,000, 그 외 기존 9,000). 상한에 걸리면 실제 적용된 증가분은 줄거나 0이 된다.
- 서비스의 한도 검사·요청 기록과 실제 어댑터의 출력 한도에 같은 증가분이 한 번만 적용된다. 과거 예약액·결과 불명·인지 확인·실패 이력은 수정/해제하지 않는다. 새로운 추정 금액 예약·임의 금액 상한은 추가하지 않았다.
- `IntelligenceRun.options`에 `script_prompt_version`, `base_max_tokens`, `max_tokens`, `output_token_allowance`를 저장한다. 기존 AIUsage의 입력/출력 사용량을 run_id로 연결해 V1/V2별 집계할 수 있다. Fake 사용량을 실청구액으로 표시하지 않는다.
- Claude `stop_reason=max_tokens`, OpenAI `finish_reason=length`는 고정된 `output_limit` 진단으로 기록한다. 응답 원문·비밀값을 남기거나 자동 후속 요청/재시도/Provider 전환을 하지 않는다.
- Claude의 버전별 JSON schema에 새 필드를 반영했다. OpenAI는 기존 JSON object 전송과 버전별 지시문·로컬 schema 검사를 유지해 전송 방식을 재작성하지 않았다. 실계정 수용 여부는 이번에 조회하지 않았다.

## 검증

- 로컬 Windows Python **3.14.7**: 변경 범위 분할 검증 **287 PASS + 8 PASS = 295건**, Ruff·pip check PASS. 초기 숏폼 4개 fixture 미연결 오류는 명시적인 Fake fixture import로 수정했고, 공급사 두 종류까지 확장된 8개 조합이 통과했다. 테스트 삭제·skip 없음.
- Windows Actions Python 3.12/3.14: 실행 결과는 아래 후속 확정 절에 기록한다. 대상은 `tools/explainer_compatibility_targets.txt`이며 이전 전체 영상 제작 443건을 반복하지 않는다.
- 검증 내용: V1 직렬화 호환, V1/V2 실제 어댑터+Fake HTTP, 30/45/60초 QUICK·STANDARD 역할/시간, 기본값·롤백·작업 고정, 편집 메타데이터 보존, Fake 영상 전달·자막/내레이션 분리, 고위험 경고, 숫자·인용·비밀정보 차단, 토큰 여유분·기록 일치, 잘린 응답 미재전송.
- 합성 자료 A(기준금리 동결)와 B(어린이집 총기 안전 사건)는 실제 보도가 아니다. Fake 분석은 A 추천·B 고위험을 반환하도록 구성했다. B 대본도 생성 거부 없이 비선정적 소재/검토 경고와 함께 저장된다. [합성 V1/V2 비교 예시](evidence/explainer-method-b/synthetic-comparison.json)는 기대 구조를 보여 주는 fixture이며 실제 모델 산출물이 아니다.
- 과거 전체 회귀 **57 FAIL 기록을 보존**한다. 이번에 전체 회귀는 반복하지 않았다. 초기 넓은 점검에서 `test_intelligence`의 기존 UI 문구 기대값과 migration `0015` 기대값 두 실패를 발견했고, 기준 HEAD 소스 복사본에서도 동일하게 2 FAIL임을 확인했다(현재 실제 schema는 0018). 해당 테스트를 삭제하거나 skip하지 않았다. 이 보고서는 전체 회귀 PASS를 주장하지 않는다.
- 실제 MP4·한국어 음질은 이번 검증 대상이 아니다. Fake 렌더 결과는 명시적으로 `simulated`, `playable=false`다. 이전 단계의 실제 로컬 FFmpeg 합성 증거를 새로운 V2 음질·영상 품질 검증으로 재사용하지 않는다.

## 남은 작업과 승인

1. 권장 다음 단계: 같은 합성/검토된 기사 묶음으로 선택한 한 Provider·모델의 V1/V2 분석·대본을 비교한다. 대상·호출 수를 정한 **별도 유료 호출 승인**이 필요하다. 실제 훅·확인할 일·고위험 판단·말투와 응답 사용량 증가율(문서 목표 약 10~30%)을 이때 확인한다.
2. 운영 적용은 별도 승인 후 기존 백업·활성 작업 확인 절차로 진행한다. 이번 작업에서 운영 코드 적용·설정 변경·앱 재시작을 하지 않았다. `v1` 롤백은 운영 시작 환경의 단일 설정이며 저장된 V2 작업을 V1로 바꾸지 않는다.
3. 실제 TTS·영상과 SNS 검증은 기존의 별도 생성·계정·공개 게시 승인이 필요하다. 방법 B 검증 때문에 새로운 인증/영상 엔진/비용 시스템을 추가하지 않았다.
