## 결과

**수정 검증 완료 / 영상 재생 검토 BLOCKED.** 사용자가 제출한 5개 장면은 Higgsfield에서 모두 `failed`로 반환됐다. 내려받은 영상은 0개이므로 이번 30초 작업의 장면 재생과 최종 합성을 수행할 수 없다. 이전에 저장된 다른 작업의 15초 영상과 구분했다.

공급사 상세 실패 사유와 실제 청구·환불 여부는 **NOT VERIFIED**다. 현재 어댑터가 보존한 상태 값만으로 이유를 추측하거나 과금이 없다고 판단하지 않는다. 공식 견적 US$3.360과 작업 한도 US$5.00은 유지됐으며 견적은 청구 확정액이 아니다.

## 원인과 최소 수정

첫 상태 확인에서 1번 장면이 실패하면 서비스가 즉시 예외를 내고, 이미 제출된 2~5번 상태를 확인하지 못했다. 실패한 1번 기록을 그대로 유지하고 접수된 나머지 장면만 조회할 수 있도록 수정했다.

- `src/newsflow/character/service.py`: `scene_review`에서도 제출 상태 장면의 조회를 허용한다. 기존 실패 상태는 건너뛰고 다른 접수 건을 확인한다. 결과 불명·제출 중·미제출 상태가 섞이면 공급사 호출 전에 중단한다. 완료 영상의 기존 검증·다운로드 계약을 유지한다.
- `tools/bat_distribution/character_manual_execution.py`: 기존 제출 핸들과 작업 범위에 한해 부분 실패 후 조회·다운로드를 연결한다. 새 제출·재시도 권한을 확대하지 않는다.
- `frontend/src/studio/core/CharacterStudio.tsx`: 남은 접수 장면이 있으면 ‘남은 장면 상태 확인’을 표시하고 실패·대기·완료 수를 구분한다. 대기 결과가 남아 있는 동안 재시도 견적은 노출하지 않는다.
- `frontend/src/studio/CommandDialog.tsx`: 상태 확인 동의를 새 생성 동의와 구분하고 조회 오류 뒤 저장 상태를 다시 표시한다.
- `tools/bat_distribution/tests/test_character_partial_results.py`, `tests/character_partial_status.test.mjs`: 부분 실패·기존 결과 수집·결과 불명 차단·추가 제출 없음·UI 조건 검증.

## 승인된 운영 확인

최초 수정 요청은 자동 승인 심사에서 추가 승인이 필요하다는 사유로 거절됐다. 변경 없이 중단한 뒤 사용자의 ‘최소 수정·Stop/Start 1회·기존 결과 확인’ 명시적 승인을 받아 진행했다.

1. 승인된 운영 파일 4개를 백업 후 반영했다. 정상 Stop 종료 코드는 0이며 Start는 1회였다.
2. 새 인증으로 열린 사용자 Chrome에서 기존 작업의 ‘남은 장면 상태 확인’을 실행했다. 새 영상 생성이나 유료 재시도는 수행하지 않았다.
3. 원래 1번 실패 기록은 완전히 유지됐다. 2~5번도 공급사 `failed` 상태로 확인됐다. 5건의 기존 핸들·요청·시도 횟수·제출 시각은 변경하지 않았다.
4. Chrome에 ‘실패 5’와 각 장면 ‘실패 · 확인 필요’를 표시했다. 재생 가능한 파일이 없으므로 재생·합성 성공을 보고하지 않는다.

이번 후속 작업의 추가 영상 제출·Claude 생성은 0회다. 사용자가 앞서 제출한 5건은 존재하므로 전체 작업을 ‘유료 호출 0회’로 표현하지 않는다. 공급사 결과 조회는 수행했다.
