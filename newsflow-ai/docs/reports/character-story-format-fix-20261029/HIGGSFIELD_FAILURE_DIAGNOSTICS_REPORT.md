## 요청 규격 대조

공식 O3 image-reference 문서에서 `mode=std`, `duration=6`(지원 범위 3~15초), `sound=on`, `aspect_ratio=9:16`, `shot_type=customize`, `multi_shots=false`가 지원됨을 확인했다. 30초는 기존 앱 계약에 따라 6초 요청 5개다. 이 옵션들만으로 요청 오류라고 단정할 근거는 없다.

장면별 프롬프트는 약 3,372~3,476자다. 확인한 공식 모델 문서에는 프롬프트 최대 길이가 명시되어 있지 않으므로, 길이 초과가 원인이라고 주장하거나 임의로 줄여 재전송하지 않았다. 계정·공급사 내부 사유·입력 내용에 따른 실패는 실제 오류 설명으로 확인해야 한다.

## 발견된 앱 결함과 최소 수정

`HiggsfieldVideoClient.check()`가 공식 상태 응답의 `error` 필드를 버리고 상태만 반환했다. 기존 실패 장면은 재조회에서도 건너뛰므로 원인 설명을 확인할 수 없었다. 이것은 **오류 표시·진단 결함**이며 영상 생성 실패의 원인으로 확정된 것은 아니다.

- 공급사 상태 응답의 오류 설명을 제한된 일반 텍스트로 보존한다. 키·키 부분·URL·경로·식별자·반사된 입력은 화면과 진단 기록에서 제거한다.
- `실패 상세 확인`은 기존 인증·Origin·CSRF·동의 경로를 사용한다. 저장된 실패·제한·취소 요청의 정확한 상태 GET만 수행한다.
- 조회 중 새 생성·재시도·참조 업로드·견적·다운로드를 허용하지 않는다. 자동 조회도 추가하지 않았다.
- 장면의 기존 실패 상태, 종료 시각, 요청 내용·핸들·시도 횟수, 스토리, 견적과 작업 한도는 그대로 두고 `status_diagnostics`만 저장한다.
- 공급사 상태가 기존 기록과 다르거나 설명이 없는 경우 이를 명시한다. 오류 문자열로 환불·과금·재시도 여부를 자동 판단하지 않는다.

## 보호 및 운영 적용 조건

이번 조사·개발에서는 운영 앱을 재시작하거나 운영 DB·키·미디어·백업·작업 파일을 수정하지 않았다. 이전 운영 확인의 기사 169건·47개 테이블·원본 및 백업 A/B 보존 증거를 재사용한다. 수정본을 운영에 로드하려면 정상 Stop·Start 1회가 필요하다. 과거 승인된 재시작은 이전 수정에 사용됐으므로 추가 승인을 받기 전 실행하지 않는다.

승인 뒤에는 백업 후 최소 코드·React 자산만 반영하고, 사용자 Chrome의 새 버튼으로 기존 5건 오류 상세를 확인한다. 오류 확인은 유료 재생성 승인이 아니며, 유료 재생성은 원인 대조 후 별도 사용자 승인을 유지한다. 현재 실패 원인 해결이나 운영 검증 완료를 보고하지 않는다.

개인 프롬프트·참조 이미지·공급사 요청 ID·계정 정보·토큰·쿠키·키·실제 작업 기록은 GitHub에 포함하지 않는다. Chrome 증거는 로컬에 보존한다. `main`, PR #35, 외부 배포는 변경하지 않는다.
