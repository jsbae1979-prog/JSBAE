## 최소 변경

- 기존 `IntelligenceService`, `APIBudgetService`, `AuditLog`를 재사용했다. 신규 DB migration·메뉴·HTTP route·비용 계산 체계는 없다.
- `comparison_review()`는 기사 A/B, 기존 결과 불명 기록, 설정·지시문·구성 계약의 지문을 읽기 전용으로 산출한다. `approve_comparison()`은 해당 지문과 명시적 동의를 확인한 뒤 별도 승인 이력만 추가한다. 기존 요청·예약액·실패·인지 확인 이력을 수정/해제하지 않는다.
- `IntelligenceService.analyze/generate`에 내부 비교 승인 번호·단계 인자를 전달하면 기존 예약 트랜잭션 안에서 범위 검사와 단계 사용 기록을 함께 저장한다. 일반 호출의 readiness는 계속 BLOCKED일 수 있다. 전역 차단을 해제하거나 결과 불명을 성공/환불/확정 거절로 바꾸는 기능이 아니다.

- 승인 유효기간은 저장 후 1시간이며 중복 저장으로 연장하지 않는다. 실제 인증 갱신 후 실행 직전에 저장할 수 있고, 인증 증거 시각 갱신이 승인 횟수를 초기화하지 않는다.
- 기사·모델·버전·길이·스타일·출력 한도·부모 분석·호출 순서·지시문·이전 결과 지문이 다르면 전송 전에 차단한다. 승인된 이전 호출이 success로 끝났고 완료 지문이 일치할 때만 다음 단계로 간다.
- 이전 요청이 실패·시간 초과·결과 불명·사용량 누락이면 후속 단계와 같은 단계 재전송을 차단한다. 새 결과 불명 요청이나 진행 중 요청이 생겨도 중단한다. 동시 요청은 기존 `BEGIN IMMEDIATE` 트랜잭션으로 단계 하나만 소비한다.
- 인증 24시간 만료, 키 미등록, 사용 승인 해제, 실제 보고 사용량에 따른 월 한도는 그대로 적용한다. Fake 예산으로 실호출을 허용하거나 인증 증거를 새로 만드는 경로는 추가하지 않았다.
