# 저장 분석 재사용 — V2 대본 2회 범위

기준 HEAD `049965548abdb9a501f135f6a0e133f1cdb22192`, 기존 격리 checkout과 Draft PR #35를 유지한다. 사용자는 저장 분석 #50을 재사용한 Claude Sonnet 4.6의 합성 A/B STANDARD 30초 대본 각 1회, 합계 최대 2회를 별도로 승인했다. 검색·재분석·인증 조회는 0회, 요청당 300초이며 실패·결과 불명·안전/분량 경고 시 남은 요청도 중단한다. 실제 음성·영상·OAuth·업로드·게시는 승인 범위가 아니다.

## 최소 보완

기존 `comparison_approval`의 5단계 계약을 보존하고, 성공한 기존 V2 분석을 재사용하는 2단계 계약만 추가했다. 별도 메뉴·migration·비용 체계는 없다. 새 승인은 기존 AuditLog에 추가하며 과거 승인·예약·결과 불명·인지 확인·실패 이력을 수정/해제하지 않는다.

재사용 분석은 같은 Provider·모델·V2, 성공한 분석/사용량 예약, 원래 완료 지문이 모두 일치해야 한다. 새 승인은 부모 분석과 사용량 기록 지문, 기사 A/B, 모델·길이·지시문·장면 계약·순서·설정·기존 결과 불명 기록을 고정한다. 기존 5회 승인을 갱신하거나 분석·검색·다른 Provider로 범위를 넓히지 않는다. 새 승인도 중복 저장으로 유효기간을 연장하지 않는다.

첫 대본의 실패·결과 불명뿐 아니라 길이·도입/마무리·합성 표시 등 재계산한 검토 경고가 있으면 두 번째 전송을 차단한다. 첫 결과가 편집/승인되거나 부모/사용량 기록이 바뀌어도 같은 범위를 재개하지 않는다. 기존 실제 인증 증거·키 등록·사용 승인·실사용량 한도 검사를 유지한다.

기존 분석의 자료 snapshot을 사용한다. 승인 후 현재 보관 기사가 바뀌어도 새 수집 내용을 해당 대본에 섞지 않는다. 분석 snapshot 또는 승인 지문 변경은 차단한다.

## Fake 검증과 사전 준비

- Windows 로컬 Python 3.14.7: 기존 비교·단일 대본 승인·검토 보호와 새 재사용 범위 **104 PASS**, Ruff(`src tests tools`) PASS. 합성 DB·키·Fake HTTP만 사용했고 실제 API·운영 데이터 변경은 0회다.
- 이전 5회 계약 보존, 새로운 2회·세 번째 차단, 부모·사용량·완료 기록·승인 만료/순서 변경 차단, 중간 시간 초과·잘못된 JSON·사용량 누락·분량/도입 경고 후 후속 차단을 검증했다. 기존 설정·결과 불명·예약액·이전 대본·분석을 비교했다.
- 초기 새 테스트의 기사 변경 기대를 저장 snapshot 사용 정책에 맞게 바로잡고, 현재 기사 편집이 승인된 전송 자료와 새 초안을 바꾸지 않는 별도 검증으로 유지했다. 실패 테스트를 skip하거나 과거 전체 회귀 57 FAIL 기록을 삭제하지 않았다. 전체 회귀는 실행하지 않는다.
- 실호출 준비는 원래 보호된 비교 DB를 새 보호 폴더에 복사했다. 운영 DB/WAL과 기존 비교 원본 해시, 키 파일 상태, 24시간 이내의 기존 인증 증거와 부모 분석 완료 기록을 확인했다. 운영 DB를 SQLite로 열거나 앱을 재시작하지 않았고, 새 인증 조회·재분석·승인 저장·유료 요청은 이 준비 시점에 하지 않았다.

Windows 3.12/3.14 변경 범위 CI와 승인된 실제 요청의 결과는 후속 보고에 구분해 기록한다. Fake PASS를 실제 대본 품질 PASS로 표시하지 않는다. 실제 요청은 영구 실행 표식과 전송 전 요청 횟수 기록을 사용하며 결과 불명 요청을 재전송하지 않는다.
