# [Codex PC 세션 전달용] NewsFlow AI Studio 전체 UX/UI 전면 교체 통합 실행 지시 — v3.0

## 결정과 목표
사용자가 NewsFlow AI 기존 기능 개발 완료를 알렸다. 신규 UX/UI 사전 설계는 완료 단계이므로, **별도 개발 브랜치에서 React + TypeScript 프런트엔드 전면 교체 작업에 착수**한다.

- 마스터 디자인은 전달 패키지의 `마스터_대시보드_사용자선정원본.png`이다. 특히 대시보드 히어로 배너/좌측 메뉴/프로젝트 카드/빠른제작/우측 현황의 배치와 시각 품질을 충실히 재현한다.
- 이전 HTML/Jinja2 화면에 CSS만 덧칠하거나 목업 이미지를 통째로 붙인 결과를 개발 완료로 간주하지 않는다. 실제 버튼·정보·작업 상태는 DOM/React 컴포넌트로 동작해야 한다.
- 기존 Python 엔진, FFmpeg, RSS/AI/캐릭터/이미지/자동화/게시 서비스, DB와 프로젝트·키·유료승인·보안 정책은 최대한 유지한다.

## 제품 아키텍처
- `newsflow-ai/frontend`에 React + TypeScript + Vite 기반 독립 프런트엔드 구성. Tailwind/shadcn/ui/Lucide 등은 구조에 적합한 경우 적용. 구성요소 통합이 목적이며 의존성 불필요 증가 금지.
- 기존 FastAPI 서비스 유지. HTML form+redirect에 결합된 변경 기능만 얇은 JSON API Adapter로 노출. 재사용 가능한 기존 JSON 상태/미디어 API는 새로 만들지 않는다.
- 전체 신규 UI 공통 Shell(240px 좌측 내비·64px 헤더, 1920/1366 해상도), 공통 토큰 및 상태/오류/승인 UI 구현. Windows 브라우저/데스크톱 실행 구조와 적절하게 연결.
- 내부 모듈 등록으로 장래 콘텐츠 자동화 종류를 확장하되 외부 플러그인 플랫폼은 선제 구축하지 않는다.

## 실제 기능 연결과 경계
- 이미지 참조 첨부는 현재 로컬 보관·재사용이며, 참조 기반 유료 이미지 편집 생성은 **NOT IMPLEMENTED**. 지원하는 것처럼 표시하지 않는다.
- AI 생성물·파일 존재·대본 검토·저작권·게시 승인을 서로 분리한다. 실계정 연결·AI 호출 성공·SNS 게시 성공·조회수 등을 임의로 표시하지 않는다.
- AI 비용·예약 금액·공급사 실제 청구액 구분. 유료 API는 별도 승인 전 실행하지 않는다.
- CSRF/Origin/CSP, local-only Host, DPAPI 자격정보 비노출, Revision 충돌, 중복 유료 요청·게시 방지, 결과 불명 자동 재전송 금지를 유지한다.
- 캐릭터 파일 저장 및 이미지 불변 산출물 저장을 무리하게 새 통합 DB로 이동하지 않는다. 프로젝트는 조회 어댑터에서 통합한다.
- 자유 드래그 트림·다중 트랙·자유 레이어 편집 등 기존 엔진 미지원 기능은 명확히 별도 개발 범위로 분류하고, 동작하지 않는 가짜 컨트롤을 만들지 않는다.

## 연속 실행 방식
A. 최신 코드와 기능 보존 매핑을 짧게 확정하고 독립 React 셸을 구축한다.
B. **먼저 원본 대시보드 + 제작 홈 두 화면을 실제 React로 구현하고 동일 조건 실제 캡처를 사용자 선정 기준 이미지와 비교**한다. 기능·디자인 인수 항목을 구분하여 보고한다.
C. 충분히 일치하면 뉴스·캐릭터·이미지 전문 제작실에 기존 API를 연결한다. 이후 다른 7개 업무 화면/초기 설정까지 동일 컴포넌트·디자인 시스템으로 연속 개발한다.
D. 각 구간 실제 동작/Visual screenshot을 확인하고 미지원 기능을 표시한다. 중복 사전점검·중복 단계·불필요한 승인 대기를 최소화한다.
E. 디자인/기능/보안/Windows 4개 Gate를 최종 점검하고 사용자가 비교 가능한 전후 캡처와 통합 보고서 및 Draft PR을 제출한다.

## 테스트·수용
- 디자인: 원본 마스터 이미지 vs 1920×1080 React 실행 화면을 시각 비교. 1366×768에서 편집 미리보기+타임라인 동시 표시. 100/125/150/200% Windows DPI 확인.
- 기능: 뉴스 → 대본 → 영상 → MP4 → 저장·재진입·게시 준비, 캐릭터 → 견적·검토 → 합성, 이미지 독립 제작 → 이미지 재사용, 이미지 카드 → 게시, 예약·중단·복구·설정·삭제 복원.
- 보안: 승인·CSRF·실제 계정·저장 경로·API 키 보호, 실패·결과 불명 케이스. 실제 유료 공급사 호출과 SNS 게시 0건 유지(별도 명시 승인 없으면).
- 기존 전체 회귀 증거는 Step15A 단일 5,454 PASS / 4 SKIP를 구분해 재사용하되 Step15B CI identity 1 FAIL을 숨기지 않는다. 제품 코드 수정분 중심 회귀를 우선 실행한다. 제품 전체 PASS를 증거 없이 주장하지 않는다.
- 새로운 중대한 UI 회귀 0을 목표로 한다. 디자인과 동작을 각각 PASS/CONDITIONAL/FAIL로 판정한다.
