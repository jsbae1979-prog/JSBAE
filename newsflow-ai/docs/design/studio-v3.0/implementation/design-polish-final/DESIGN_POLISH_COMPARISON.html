3. 재현 여부와 원인 구분
- 재현: 1920 제작 홈에서 디코딩 전 naturalWidth=0/complete=false. 해당 이미지 응답은 200, decode 대기 후 naturalWidth=235/230/235. 이는 캡처 시점의 일시적 빈 상태이며 지속적인 이미지 누락은 재현되지 않았습니다. Lazy loading은 유지했고 정적 예시 그림으로 실제 결과를 대체하지 않았습니다.
- 재현: 모의 HTTP 404에서 기존 onError는 img.hidden=true만 설정해 텍스트 없는 빈 영역을 남겼습니다. 이제 로딩 중 상태와 실패/부재 상태가 구분되고 404 후 미리보기 없음·img 0개를 확인했습니다.
- 재현: 캐릭터 참조 이미지가 완성 영상 미리보기 아래에 있어 첫 화면에서 확인되지 않음. 참조 패널을 위로 이동해 합성 PNG naturalWidth=32가 두 viewport 첫 화면에 나타남을 확인. 참조 없음도 별도 1366 캡처로 확인했습니다. 실제 사용자 PNG를 읽거나 복사하지 않았습니다.
- 재현: 라이브러리의 design-art-* 자산에 박힌 시간 그림이 길이로 보임. 라이브러리에서 이 장식 자산을 제외했고 실제 검증 썸네일 URL은 계속 사용합니다. 길이 숫자를 추정·추가하지 않았습니다.
- 재현: 같은 이름의 키 저장 버튼. 표시 이름만 공급사별로 분리했고 원래 폼/선택 Provider/동의/저장 동작은 그대로입니다. 세 대화창의 비밀 입력이 모두 빈 상태임을 확인했습니다.
- 재현되지 않음: 정상 응답 이미지의 지속적 빈 칸, 홈 상단 구조 변경, 가로 넘침. 따라서 lazy/eager 전체 전환, 히어로 재제작, 폰트 확대 등은 하지 않았습니다.
