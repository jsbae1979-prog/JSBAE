# Phase 5A · 간편 자동 제작

Autopilot은 사용자가 시작한 한 작업에서 뉴스 수집, 뉴스 선택, 기본 대본 생성, 검토영상 제작, 파일 검사, 게시 대기함 보관을 이어서 실행합니다. 예약 실행이나 실제 SNS 게시 기능은 없습니다. 운영 대상은 Windows 11이며 기본 주소는 `http://127.0.0.1:8765`, 데이터 폴더는 `%LOCALAPPDATA%\NewsFlowAI`입니다.

## 처음 사용하는 경우

Python 3.12와 FFmpeg/ffprobe를 준비하고 `newsflow-ai\run.bat`를 실행합니다. 자세한 설치·업데이트·오류 해결은 [README](../README.md)를 참고하세요. BAT는 Python 가상환경과 패키지를 준비하며 FFmpeg나 글꼴을 자동 설치하지 않습니다.

홈의 **자동 제작 시작**을 누르면 저장된 기본값으로 제작합니다. 첫 기본값은 **간편 제작 · 체험 뉴스 · 30초 · YouTube용**입니다. 별도 API 키나 계정 연결 없이 기본 대본과 무음 검토영상으로 흐름을 확인할 수 있습니다.

체험 뉴스는 프로그램에 포함된 가상 기사입니다. 실제 보도·현재 화제성을 나타내지 않으며 발행시각을 만들어 넣지 않습니다. 출처 이름과 게시 초안 설명에도 합성 자료임을 표시합니다. 예제 URL은 출처 표시에만 사용하며 이 모드에서 외부 RSS 서버에 요청하지 않습니다.

**기본 대본**은 Offline Provider가 만든 편집용 틀입니다. 실제 외부 AI 분석·작성 결과가 아닙니다. 영상은 실제 FFmpeg로 만드는 **1080×1920 H.264/AAC MP4**이며 AAC 오디오는 무음입니다. 음성 합성 품질을 확인한 결과로 해석하지 마세요. 화면에 검토용 초안임을 표시하고 사람의 검토 상태는 그대로 유지합니다.

영상 제작 도구·한국어 글꼴·저장 공간을 확인할 수 없으면 해당 단계에서 멈춥니다. 테스트용 Fake Render가 만든 재생 불가 파일을 완성 MP4나 게시 대기 영상으로 표시하지 않습니다.

## 간편 제작과 단계별 제작

| 방식 | 사용 흐름 | 사용자가 확인하는 시점 |
|---|---|---|
| 간편 제작 | 홈에서 시작 → 진행률 확인 → 완성 영상/게시 대기함 | 시작 설정과 최종 결과 |
| 단계별 제작 | 자동 제작 메뉴에서 방식 선택 → 뉴스 선택 → 대본 확인·수정 → 영상 확인 → 대기함 | 뉴스·대본·영상의 세 확인 지점 |

단계별 제작은 다음처럼 진행합니다.

1. **자동 제작**에서 **단계별 제작**, 길이, 목적지, 뉴스 종류를 선택하고 시작합니다.
2. **이 뉴스로 만들어 볼까요?** 화면에서 이번 수집 출처의 후보 중 뉴스를 선택합니다. 기존 내부 추천 점수는 조회수나 검색량을 측정한 값이 아닙니다.
3. 대본이 준비되면 제목·요약·장면별 문장을 읽습니다. **대본 수정**으로 AI Studio에서 편집·저장한 뒤 작업 화면으로 돌아와 다음 단계로 진행합니다.
4. 영상이 준비되면 플레이어로 확인합니다. **게시 대기함에 보관하기**를 눌러 로컬 초안을 저장합니다.

다음 단계로 진행하는 동작은 사실 확인·저작권 확인·SNS 게시 승인으로 기록되지 않습니다. 영상 제작 후 대본을 바꾸면 기존 영상은 바뀐 대본을 반영하지 않습니다. 대본과 영상의 revision이 맞지 않으면 대기함 등록을 차단하므로, 이미 제작한 결과를 수정하려면 고급 Video Studio에서 변경한 대본을 확인하고 새로 제작하세요. 기존 MP4를 덮어쓰지 않습니다.

## 뉴스와 대본 선택 범위

**체험 뉴스**는 내장 RSS 바이트를 FakeRSSAdapter에 전달하되 기존 파싱·중복 제거·분류·DB 저장 서비스를 사용합니다. 체험 출처를 사용자 RSS 목록의 활성 상태로 바꾸거나, 등록된 실제 출처까지 함께 요청하지 않습니다.

**등록한 뉴스 출처 수집**은 사용자가 Settings에서 등록하고 활성화한 공개 RSS만 요청합니다. 이 선택은 시작 화면과 간단한 설정에서 인터넷 수집임을 안내합니다. 한 작업에 최대 20개 출처를 사용하며 TLS·SSRF·robots·타임아웃 정책은 기존 수집과 같습니다. 전체 수집이 성공하지 않으면 자동 제작을 다음 단계로 진행하지 않습니다. 부분 수집 결과와 기존 기사는 삭제하지 않습니다.

뉴스 후보는 해당 수집 출처의 저장 기사 중 기존 자동 제작 작업이 사용하지 않은 기사에서 선정합니다. 새로 추가된 기사만을 의미하지 않으며, 이미 저장되어 중복 처리된 기사도 아직 제작에 사용하지 않았다면 후보가 될 수 있습니다. 원문 본문이나 외부 이미지·영상은 다운로드하지 않습니다.

Autopilot의 분석·대본 생성은 **Offline 전용**입니다. 환경변수에 AI API 키가 있어도 외부 Provider로 전환하지 않습니다. 기존 AI Studio의 외부 Provider는 각 호출의 명시적 동의 경계를 유지하며, Autopilot은 이 동의를 대신 만들지 않습니다. 목소리·자막·로컬 소재를 상세 조정할 때는 기존 Video Studio를 사용합니다.

## 단계별 기록과 결과 보존

한 작업은 고유한 32자리 작업 번호를 갖습니다. SQLite에는 다음 여섯 단계의 시작·완료·오류 이력, 시도 번호, 진행률, 산출물 참조를 보존합니다.

`뉴스 모으기 → 뉴스 고르기 → 대본 만들기 → 영상 만들기 → 영상 확인하기 → 게시 대기함에 보관`

수집 이력, 기사, 분석/대본 작업, 대본, 영상 프로젝트/렌더 작업, 게시 초안은 기존 서비스의 기록과 연결합니다. MP4 원문은 DB에 넣지 않으며 `%LOCALAPPDATA%\NewsFlowAI\outputs\videos\video-<고유번호>.mp4`에 저장합니다. 작업 화면의 **내 PC 저장 위치**, 미리보기, **MP4 저장**으로 확인할 수 있습니다. 브라우저에서 저장하는 사본의 위치는 브라우저 설정을 따릅니다.

영상 검사는 파일 존재, 경로 안전성, SHA256, 독립 ffprobe 결과의 MP4/H.264/AAC, 1080×1920, 길이와 프레임률을 확인합니다. 검사와 대기함 보관 사이에 내용이 달라지면 보관을 차단합니다. 이 검사는 내용의 진실성·저작권·플랫폼 게시 자격 검증과 별개입니다.

게시 대기함은 기존 `PublishDraft`와 검증 기록을 사용합니다. 계정은 지정하지 않으며 내용·저작권·출처 확인 플래그는 모두 미확인입니다. `completed`는 이 로컬 워크플로의 완료이고 게시 성공이 아닙니다. `PublishDraft`의 실제 게시 준비 상태는 계속 `blocked`입니다.

## 취소·재시도·재시작

| 상태 | 의미와 다음 동작 |
|---|---|
| 준비/제작 중 | 현재 작업이 실행 슬롯을 사용합니다. 다른 자동 제작은 시작하지 않습니다. |
| 확인 대기 | 단계별 제작의 사용자 확인을 기다립니다. 다음 단계 진행 또는 취소를 선택합니다. |
| 취소 | 추가 단계를 시작하지 않습니다. 이미 기록된 기사·대본·영상·초안은 보존합니다. |
| 실패 | 실패한 단계를 표시합니다. 원인을 확인하고 안전하게 재개 가능한 작업만 명시적으로 다시 시도합니다. |
| 중단 | 앱 종료 등으로 끝을 확인하지 못했습니다. 기록을 확인하고 허용되는 경우에만 다시 시도합니다. |
| 완료 | 실제 검토영상 검사와 로컬 대기함 등록이 끝났습니다. 사람의 검토가 필요합니다. |

**제작 취소**는 즉시 모든 기록을 지우는 동작이 아닙니다. 이미 시작한 수집·분석 등이 종료/타임아웃에 도달할 때까지 잠시 기다릴 수 있습니다. 렌더 취소는 해당 렌더 작업에만 전달하며 별도로 실행한 수동 작업을 취소하지 않습니다. 취소 직전에 완료된 산출물은 기록하고 후속 단계는 시작하지 않습니다.

앱을 다시 켜면 실행 중이던 작업을 자동으로 완료하거나 재실행하지 않습니다. 미완료 시도는 결과 불명으로 기록하고 작업은 중단 상태가 됩니다. 이미 확인을 기다리던 단계별 작업과 저장된 결과는 계속 조회할 수 있습니다. 다른 프로세스가 실제로 작업 중인 경우 그 작업을 재시작 복구로 덮어쓰지 않습니다.

재시도는 같은 작업 번호에서 시작합니다. 기존 결과의 기사·대본·영상 연결과 작업 상태를 확인해 재사용하며, 아직 실행 중이거나 안전한 재개 여부를 확인할 수 없는 결과는 재시도하지 않습니다. 게시 초안은 작업 번호당 하나만 생성하여 보관 직후 종료된 경우에도 같은 초안으로 연결합니다. 결과 불명인 작업을 성공으로 바꾸거나 외부 호출을 자동 반복하지 않습니다.

여러 창의 동작 충돌은 revision 확인으로 거부합니다. 다른 창에서 상태가 바뀌었다면 새로고침 후 최신 상태에서 다시 선택하세요. 실행 잠금과 DB의 단일 활성 슬롯으로 중복 실행을 막으며, 확인 대기 작업도 활성 슬롯을 유지합니다.

## 같은 뉴스 중복 제작 정책

자동 선정한 기사 ID는 해당 작업에 예약합니다. RSS 단계의 URL·유사 제목 중복 제거 후의 기사 ID를 사용하므로 다른 Autopilot 작업은 같은 기사를 다시 선정하지 않습니다. 단계별 제작에서 대본 생성 전에 후보를 변경하면 예약 기사도 변경됩니다.

실패·취소 뒤에도 선택된 기사의 예약은 유지합니다. 기존 작업에서 안전하게 재시도하거나 다른 뉴스로 새 작업을 만드세요. 취소했다고 별도 작업으로 같은 영상을 자동 복제하지 않습니다. 이 정책은 Autopilot에 적용하며 고급 Video Studio의 명시적 수동 편집·재제작을 금지하는 기능은 아닙니다.

체험 뉴스의 수는 유한합니다. 모두 제작에 사용하면 같은 자료를 새 기사로 꾸미거나 날짜를 바꿔 재생성하지 않고, 제작할 후보가 없음을 안내합니다. 데이터베이스를 삭제하여 중복 정책을 우회할 필요는 없습니다.

## DB 업데이트와 경계

Additive migration `0008`은 작업·시도·이벤트·산출물·기사 예약 테이블, 영상의 `preview_only`, 게시 초안의 고유 `autopilot_task_id`를 추가합니다. 기존 `0001`~`0007`을 수정하지 않습니다. 업데이트 전 앱을 종료하고 사용자 데이터 전체를 백업하세요. 업데이트된 DB를 이전 브랜치 코드로 운영하지 마세요. 기존 이전 도구는 DB와 세션 키를 복사하며 영상·소재·기타 사용자 파일은 별도 백업해야 합니다.

기존 CSRF·Origin/Host·CSP·SSRF·TLS 정책을 유지합니다. Autopilot은 실제 OAuth 시작, Google/Instagram 로그인, 서비스 토큰 발급·저장, MP4 외부 전송, 실제 SNS 업로드·게시를 실행하지 않습니다. 간단한 설정이나 환경변수로 이 경계를 해제하지 않습니다. 계정 연결 승인과 게시 승인은 별도입니다.
