# 참고 이미지 완전 구현 — 다음 개발 범위 검토안

상태: **사용자의 “모두 진행해 주세요”로 1~5단계 로컬 구현 승인. 실계정 실행·원격 변경 제한은 유지.**

사용자는 이미지의 시각적 배치뿐 아니라 TikTok/Facebook, 실제 성과·수익 통계, 게시 시각 추천의 실제 기능도 원하며, 먼저 별도 개발 범위를 확인하기로 선택했습니다. 기존 원격 push·PR 변경·병합·실계정 연결·유료 호출·업로드/게시 제한은 유지합니다.

## 기준과 현재 구현

- 원본의 6개 화면을 시각적 기준으로 사용. 화면별 구조·열 너비·간격·아이콘·글꼴·상태·탭 동작을 대응표로 관리하고, 같은 크기의 실제 앱 캡처와 원본을 나란히 비교할 것.
- 기존 YouTube/Instagram 게시 경로: `publishing/youtube.py`, `publishing/instagram.py`, `publishing/unified.py` 및 관련 GUI/OAuth 경로를 재사용.
- 현재 Facebook Login for Business 코드는 Instagram 연결 경로임. **Facebook 자체에 게시하는 Adapter가 있다는 뜻이 아님.**
- `scheduler/`는 제작 예약. SNS 게시 캘린더/예약과 구분.
- 현재 제작 활동 그래프는 저장된 제작 기록. 실제 플랫폼 조회수·구독자·수익 수집 엔진으로 간주하지 않음.
- 현재 영상 타임라인은 대본 장면 선택/편집 연결. 임의 효과 편집·다중 오디오 믹싱·뉴스 앵커 생성 엔진으로 간주하지 않음.

## 제안 단계

| 단계 | 실제 개발 내용 | 완료 증거와 경계 |
|---|---|---|
| 1. 화면 일치 기준 | 원본 6화면의 구성요소별 대응표, 원본과 동일한 정보 계층/배치, 실제 탭/편집/메뉴 연결, 모든 데이터의 출처·상태 구분 | 같은 뷰포트 전후 캡처 및 실제 동선. 보유하지 않은 통계나 계정 연결을 성공값으로 채우지 않음 |
| 2. 플랫폼 확장 | 공식 문서 확인 후 TikTok 게시 Adapter/OAuth 설계, Facebook Page 영상/Reels 게시 Adapter, 기존 통합 게시 작업에 플랫폼별 상태·승인·재시작 복구 연결 | Fake API 계약/권한 축소/중복 방지/부분 성공/결과 불명 검증. 실계정 연결·업로드는 별도 승인 후 |
| 3. 실제 성과 분석 | 플랫폼별 수집 Adapter, 영상과 플랫폼 콘텐츠 ID 매핑, 조회/도달/참여/구독자 변화/수익의 제공 여부와 정의 구분, 기간별 저장 및 차트 | 반환된 실제 필드만 표시. 제공되지 않거나 권한이 없는 수익은 '미지원/확인 불가'. 누락값을 0이나 추정 매출로 표시하지 않음 |
| 4. 게시 캘린더 | 실제 게시 계획과 플랫폼별 실행 상태, KST 표시, 승인된 콘텐츠의 예약 실행 정책, 수정 시 승인 재검토, 미실행/결과 불명 복구 | 제작 예약과 구분. 앱 종료/절전 시 정책 명시. 승인 없는 자동 게시 및 무조건 재시도 금지 |
| 5. 게시 시각 추천 | 충분한 실제 게시/성과 표본에 한해 시간대별 추천, 표본 수·분석 기간·근거 공개 | 자료 부족은 '추천 자료 부족'. 조회수/수익 보장이나 임의 성능 예측 금지. 외부 AI 분석을 쓰려면 별도 전송·비용 동의 |

## 착수 전에 확정할 공급사 조건

아래 사항은 이번 범위 검토에서 공식 문서를 재조회하거나 실제 계정으로 확인하지 않았으므로 **NOT VERIFIED**입니다. 공급사 확인 결과에 따라 기능 범위가 제한될 수 있습니다.

- TikTok: 공식 게시 API의 앱 등록/검수, 계정 자격, 권한, 게시 유형/공개 범위, 업로드 제공 방식, 사용량 제한.
- Facebook: Page/Reels의 현재 공식 지원 범위, 필요한 Page 권한/앱 검수, 토큰 수명·해제, Instagram 권한과의 차이.
- YouTube/Instagram/TikTok/Facebook 성과 API: 제공 지표, 지표 정의, 수익 제공 자격, 보관/조회 기간, 권한/쿼터.
- 예약 게시: 플랫폼 자체 예약 지원 여부와 로컬 앱 예약의 차이, 정책상 허용되는 실행 방식.
- 추천: 확보 가능한 실제 성과 데이터와 최소 표본 기준. 검증 전 특정 AI 모델/가격/예측 정확도를 약속하지 않음.

## 추가 범위로 분리할 요소

원본의 가상 뉴스 앵커, BGM/효과 트랙, 임의 영상 템플릿, 지도/히트맵에 필요한 실제 데이터가 기존 엔진에 없으면 별도 기능으로 목록화합니다. 화면에 장식을 그려 넣는 것으로 실제 기능 개발 완료를 대신하지 않습니다. 사용권이 확인된 소재만 사용하며 새 유료 영상/음성 엔진을 임의로 추가하지 않습니다.

## 승인과 작업 방식

이 문서의 1~5단계는 후속 사용자 승인으로 착수했습니다. 세부 구현·제약은 `../design/social_platform_operations.md`를 따릅니다. 우선 **화면별 차이 목록과 공식 API 가능 범위 조사 → Fake 기반 구현 → Cloud/Windows CI → 별도 승인된 실계정 검증** 순서를 권합니다.

신규 데이터 모델이 필요하면 additive migration을 제안하고 기존 DB/키/작업/승인 기록을 보존합니다. 구현 승인과 실계정 인증·외부 전송·게시 승인은 구분합니다. 원격 브랜치/PR 운영 방식도 기존 제한을 바꾸려면 별도 지시가 필요합니다.
