## 필요한 부분만 수정

1. 신규 V2 요청의 장면별 발화 예산에 **공백·문장부호를 포함한 최대 글자 수**와 문장 수를 명시한다. 기본 30초 STANDARD의 예시는 `36/55/55/51자`, 총 197자 안내다. 첫·마지막 장면은 최대 2문장, 중간 장면은 각각 다른 핵심의 1문장이다. QUICK·30/45/60초·저장된 속도와 쉼에도 같은 계산을 적용한다.
2. 기존 발화 단위 상한에 공백·문장부호를 위한 작성 여유를 둔 1.5배 글자 상한을 함께 제공한다. 이 비율은 글쓰기 가이드이며 실제 한국어 발화 속도나 음질 측정이 아니다. 기존 SAPI 발화 추정식·실제 WAV 길이 검사도 계속 적용한다. 글자 수만 통과했다고 길이·사실성을 승인하지 않는다.
3. 중간 장면의 문장 수를 줄인 계획에 맞춰 쉼 추정과 전체 발화 목표를 계산한다. 기존 `speech_seconds`/`speech_plan` 계산식과 선택한 음성·속도는 바꾸지 않는다. 숏폼은 기존 한 문장 규칙과 3초 이내 훅 동선을 유지한다.
4. Claude에 전달하는 기존 JSON schema의 `description`에서 신규 분량 계약이 있을 때 공통 `400자` 안내를 장면별 숫자로 교체한다. V2 시스템 지시문의 공통 400자 안내도 제거한다. 새로운 wire schema 제한 키워드나 전송 형식은 추가하지 않는다. 기존 로컬 400자 안전 상한과 V1 wire/지시문은 보존한다. OpenAI는 기존 JSON object 전송과 동일 분량 계약을 사용한다. 공급사의 문법적 길이 보장을 새로 확보했다고 주장하지 않는다.
5. 응답·편집 검토에서 실제 글자 수·문장 수 초과를 경고로 남긴다. 초안과 응답 사용량은 그대로 저장해 수정할 수 있고 자동 제작은 기존 안전 검사에서 중단된다. 같은 문장 반복은 편집 안내(info)여서 기존 문체 검사 정책처럼 그 자체로 제작을 하드 차단하지 않는다. 문장을 임의로 자르거나 추가 API 요청으로 고치지 않는다.
6. `scene-characters-v1`이라는 서버 소유 계약 표시가 있는 새 작업만 새 글자 검사를 적용한다. 기존 대본·기존 계약·승인 상태는 소급 변경하지 않는다. 장면 초를 편집하면 해당 초에 맞춰 안내를 다시 계산한다. 사용자가 명시한 작업별 속도도 검사에 반영하되 원래 저장된 기본값·내레이션·전역 설정은 바꾸지 않는다.

새 메뉴·UI 개편·DB migration·음성/영상 엔진·비용 체계는 없다. Provider와 선택 모델을 바꾸거나 출력 토큰 상한을 늘리지 않는다. 출처·수치·직접 인용·비밀정보 보호, 도입/마무리 연결, 합성 표시, 결과 불명 재전송 금지를 유지한다.
