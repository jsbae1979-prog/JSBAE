# NewsFlow AI 비공개 설치·오프라인 업데이트 안내

현재 파일은 **무서명 개발 검증 후보**다. 실제 사용자에게 전달하거나 운영본을 교체하지 않는다. 신규 샘플 12개도 `rightsVerified:false`다.

## 보관 파일

- `NewsFlowAI_Setup_v1.0.0.exe`: 현재 사용자 전용 최초 설치 후보.
- `NewsFlowAI_Update_v1.1.0.exe`: 오프라인 업데이트 후보. 배포자 인증서가 등록되지 않아 실행 시 차단되는 것이 현재 정상 동작이다.
- `SHA256SUMS.json`, 구성요소 목록, `corresponding-sources/`: 후보와 함께 보관한다. 실행 파일은 GitHub에 게시하지 않는다.

## 최초 설치와 실행

권리·서명 승인 후 실제 전달할 때의 절차다. 현재 검증 후보는 지정된 합성 환경에서만 설치한다.

1. Windows 11에서 전달받은 파일의 SHA-256과 배포자 서명을 별도로 확인한다.
2. 최초 설치 파일을 실행한다. 관리자 권한, Python, Node.js, 별도 FFmpeg 설치가 필요 없는 사용자별 구성이다.
3. 기본 프로그램 경로는 `%LOCALAPPDATA%\Programs\NewsFlowAI-Private`다. 현재 후보는 이 경로만 지원한다.
4. 사용자 데이터는 `%LOCALAPPDATA%\NewsFlowAI-Desktop\v1`에 저장한다. 기존 운영 프로필 `%LOCALAPPDATA%\NewsFlowAI`를 자동으로 가져오지 않는다.
5. 설치 후 `NewsFlowAI.exe`를 실행한다. OS가 배정한 loopback 포트를 사용하며 운영 포트 8765를 사용하지 않는다.
6. 일회용 연결 인증과 세션 쿠키가 유지된다. 주소나 접속 인증 값을 다른 사람에게 전달하지 않는다.
7. 설치 프로그램은 앱을 자동으로 실행하거나 예약 작업을 등록하지 않는다. 현재 콘솔 기반 후보의 정상 종료는 콘솔의 Ctrl+C/정상 콘솔 종료 절차를 이용한다. 강제 종료를 정상 종료로 처리하지 않는다.

## 오프라인 업데이트

실제 배포자 인증서가 준비되고 서명한 파일만 실행 가능하다. 무서명 후보로 실제 업데이트를 시험하는 허용 옵션은 없다.

1. 현재 앱을 정상 종료한다. 실행 중이면 파일 잠금을 강제로 풀거나 프로세스를 종료하지 않고 업데이트를 중단한다.
2. 배포자 서명·타임스탬프·인증서 SHA-256 고정값과 파일 무결성을 검증한다. 자동 다운로드 서버는 없다.
3. 설치 버전, 지원 경로, 증가하는 업데이트 순서와 새 버전을 확인한다. 현재 정의는 `1.0.0 → 1.1.0`이다.
4. 새 프로그램을 독립 버전 폴더에 준비하고 사용자 프로필을 백업한다. DPAPI 암호문은 복호화하지 않고 그대로 복사한다.
5. 백업 후 동일 소스 리비전의 migration을 실행하고 SQLite 무결성, 새 런타임·React 파일·FFmpeg를 검사한다.
6. 통과한 경우에만 현재 버전 포인터를 전환한다. 이전 프로그램과 백업은 보존한다.
7. 완료 후 앱을 일반 진입점으로 실행한다. 현재 업데이트의 자동 검사는 migration/런타임 사전 점검이며, 사용자 전체 작업 성공을 보증하는 실제 GUI 인수 검사와는 다르다.

서명 검사의 오프라인 인증서 체인·폐기 확인 동작은 실제 배포자 인증서 확보 후 인터넷이 끊긴 새 PC에서 검증해야 한다. 현재 이를 PASS로 표시하지 않는다.

## 실패·전원 중단 복구

- 복사·migration·런타임 점검의 확인된 실패는 백업을 검증하고 이전 버전 포인터와 알려진 데이터 파일을 복원한다.
- 전원 중단/프로세스 중단으로 결과가 불명확하면 정상 실행과 업데이트 재시도를 차단한다. 자동 반복하지 않는다.
- 앱이 종료된 상태에서 `NewsFlowAI.exe --recover-update`로 명시적 복구를 요청한다. 이 명령은 보관된 백업으로 복구하며 새 업데이트를 다시 실행하지 않는다.
- 백업이 손상되거나 소유권/잠금 확인에 실패하면 복구를 강행하지 않는다. 프로그램과 데이터 폴더를 보존하고 담당자에게 비민감 오류 상태만 전달한다.
- 백업은 사용자 데이터 경로의 `update-backups/<transaction>/`에 남는다. 기존 DB·키·미디어를 임의로 삭제하지 않는다.
- 실패한 후보 버전 폴더는 조사용으로 남을 수 있다. 확인 없이 삭제하거나 같은 버전을 반복 적용하지 않는다.

## 제거·재설치

사용자별 설치 항목으로 제거한다. 먼저 정상 종료하고 미완료 업데이트가 있으면 복구한다. 검증된 프로그램 파일만 제거하고 DB·키·미디어·샘플 복사본·숨김 상태·업데이트 백업은 보존한다. 알 수 없는 파일이나 변경된 프로그램 파일이 있으면 강제 삭제하지 않는다. 같은 사용자로 재설치해도 기존 데이터는 덮어쓰지 않는다.

## 서명 순서 — 실제 실행 전 외부 인증서 필요

1. 배포자 소유의 코드 서명 인증서를 확보하고 공개 인증서 DER의 SHA-256을 검토한다. Windows 인증서 선택에 사용하는 SHA-1 thumbprint와 혼동하지 않는다.
2. 빌드에 포함할 `publisher-trust.json`에 승인한 인증서 SHA-256과 private 채널 사용 조건을 반영한다. 환경변수나 사용자 옵션으로 서명 검사를 끄지 않는다.
3. 자체 실행 파일을 서명한 뒤 payload 파일 해시를 다시 계산한다. 내부 파일 서명으로 바뀐 바이트가 최종 매니페스트에 포함돼야 한다.
4. 새 매니페스트로 Update와 Setup을 빌드하고 마지막에 외부 파일을 서명한다. 서명 후 최종 파일 SHA-256을 기록한다.
5. SignTool의 SHA-256 파일 서명·RFC3161 타임스탬프 및 `verify /pa /all /v` 절차를 따른다. 인증서 비밀번호/개인 키를 명령 이력, 문서, GitHub에 기록하지 않는다.
6. 실제 인증서의 서명 성공, 잘못된 배포자·변조·다운그레이드 차단, 오프라인 설치·업데이트·복구를 별도 검증한다. 테스트 인증서 성공을 실제 배포 인증서 성공으로 표시하지 않는다.

공식 절차: [Microsoft SignTool](https://learn.microsoft.com/en-us/windows/win32/seccrypto/using-signtool-to-sign-a-file).

## 외부 전달 전 필수 조건

- 신규 샘플과 포함된 기타 자산의 실제 사용·재배포 권리 확인.
- 실제 배포자 서명 및 완전 오프라인 진위 검증.
- 바이너리와 대응되는 FFmpeg 소스 7개, 변경/빌드 명령, 의존성·런타임 고지의 함께 전달·보존 체계.
- 실제 Windows 11 신규 표준 사용자에서 설치·업데이트·장애 복구 확인. 기존 Windows Server 두 사용자 격리 결과와 구분한다.
- 기존 운영 프로필을 채택하는 migration은 별도 승인·검증 대상이며 이번 설치가 자동 수행하지 않는다.
- 실제 사용자 전달 및 운영 교체에 대한 별도 승인.
