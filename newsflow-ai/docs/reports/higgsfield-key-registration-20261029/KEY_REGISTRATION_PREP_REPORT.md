# Higgsfield 정상 키 등록 준비 및 개발 자격정보 확인

2026-10-29. 판정: **CONDITIONAL — 실제 키 등록 완료, 공급사 권한·새 음성 영상은 미검증**.

## 사용자 요청

Higgsfield API 키를 Chrome에서 직접 다시 등록한다. 개발 환경에 실제 등록된 API 키가 있으면 제거한다. 키 원문을 출력하지 않고, 유료 영상의 결과 불명 상태와 중복 요청 방지·기존 데이터·백업을 보존한다.

## 직접 원인 및 수정

현재 운영본의 검증용 실행 경계는 `/video-ai-settings/key`를 거절하고, 일반 DPAPI 저장 기능도 비활성화했다. 키 등록까지 유료 실행과 함께 막혀 있던 연결 문제다. V3 또는 Higgsfield가 로컬 키 저장을 차단한 것으로 해석하지 않는다.

- 신규 모듈: `tools/bat_distribution/higgsfield_key_registration.py`.
- 기존 정상 운영 실행기의 연결 3곳: `tools/bat_distribution/windows_live.py`.
- 집중 합성 검사: `tools/bat_distribution/tests/test_higgsfield_key_registration.py`.
- 향후 패키징 누락 방지: 기존 `bundle_assembly.py` 구성 목록에 신규 모듈 1개만 등록했다. ZIP을 다시 만들지는 않았다.
- 기존 React 키 등록 화면과 제품 API를 재사용한다. UI 재설계·DB migration·새 승인 파일·새 만료 절차는 추가하지 않는다.
- 정상 운영에서 정확한 `POST /video-ai-settings/key`만 기존 LocalAccess·CSRF·Origin을 거쳐 처리한다.
- 현재 사용자 프로필의 `video-ai-key.dpapi`에 기존 전용 entropy로 암호화 저장만 허용한다. 전역 복호화·OAuth·임의 네이티브 실행·외부 유료 호출은 계속 차단한다.
- 이전 암호문은 사용자 프로필의 비공개 백업에 보존하고, 새 파일은 원자적으로 교체한다. 키 원문·암호문·키 식별 해시는 응답·로그에 넣지 않는다.
- 키 입력·확인·저장은 사용자가 Chrome에서 직접 수행한다.
- 기존 영상 결과 불명 상태, 승인 한도와 호출 횟수 기록은 변경하지 않는다. 키 재등록으로 영상 재전송을 허용하지 않는다.

## 개발 키 확인·제거 결과

`DEV_CREDENTIAL_REMOVAL_RESULT.json` 참고.

- 개발 코드·설정 3,403개 텍스트 파일에서 실제 공급사 키 형식의 발견 항목 없음.
- 개발 저장소와 로컬 개발 설정의 실제 자격정보 파일 없음.
- API 키 관련 Process/User/Machine 환경변수 등록 항목 없음.
- 따라서 실제 키 삭제 **0건**. 존재하지 않는 키를 삭제했다고 보고하지 않는다.
- 예제·합성 검사 키는 실제 키로 취급하지 않는다. 운영 프로필·원본·보호 백업은 삭제 범위에서 제외했다.
- 정적 형식·등록 위치 검사이며, 공급사 유효성 확인이나 실제 키 복호화는 수행하지 않았다.

## 신규 집중 검증

**17 PASS / 0 FAIL / 0 ERROR**, Fake cipher와 임시 합성 프로필만 사용했다. 기존 전체 회귀·Guard 감사·기존 테스트는 반복하지 않았다.

확인 범위: 정상 인증·CSRF·Origin의 정확한 저장 요청, 미인증·잘못된 CSRF/Origin 차단, 경로·entropy 제한, 기존 암호문 백업, 암호화 실패 시 원본 보존, 평문 버퍼 정리, 복호화·삭제·유료 경로 차단, 기존 캐릭터 호출 기록 불변, 검증 모드에 저장 연결을 설치하지 않음.

실제 DPAPI·운영 키 저장·공급사 호출은 이 검사에서 수행하지 않았다. 소스 수정만으로 운영 키가 바뀌지 않는다.

## 승인된 운영 반영 결과

사용자가 수정 반영과 **정상 Stop·Start 1회**를 승인했다. 정상 Stop 종료 코드 0 확인 후 프로필 백업을 검증하고, 준비한 실행기 연결 및 신규 등록 모듈 2개를 무결성 목록과 함께 반영했다. 기존 Chrome 자동 열기·인증 수정은 보존했다. 정상 Start를 정확히 1회 호출해 새 Chrome 인증과 설정 화면을 확인했다.

운영 코드 기준은 `a9db85128ba587a2e8ca240fc060e7ccd569fc73`다. 전환 전 PID 39644, 재시작 후 PID 10192이며 포트 설정은 18768 그대로다. 정리·강제 종료·추가 재시작은 수행하지 않았다.

Chrome에서 기존 키 등록 화면을 열었고 사용자가 직접 입력·저장했다. 키 원문은 읽거나 출력하지 않았다. 보호 파일의 교체와 이전 암호문의 비공개 백업 1개가 일치함을 확인했다. 저장 성공은 API 권한 확인이나 영상 생성 성공을 의미하지 않는다.
