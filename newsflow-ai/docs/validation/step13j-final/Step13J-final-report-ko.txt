4. Windows 설치형 EXE의 남은 필수 조건

공식 문서상 PyInstaller와 Nuitka는 Python 3.14 지원을 명시한다. 문서 지원은 NewsFlow의 Python 3.14.7 실제 빌드 성공과 다르다. 현재 점검한 64bit 격리 venv에는 두 패키징 도구가 없으며 설치·빌드 0회, 도구 선택도 미확정이다. [PyInstaller 변경 이력](https://pyinstaller.org/en/stable/CHANGES.html), [PyInstaller 요구사항](https://pyinstaller.org/en/stable/requirements.html), [Nuitka 4.2 공식 발표](https://nuitka.net/posts/nuitka-release-42.html), [Nuitka 공식 사용 설명서](https://nuitka.net/user-documentation/user-manual.html)

남은 배포 차단 조건은 다음과 같다.

- run.bat의 Python·venv·pip 전제, SAPI의 sys.executable -m 실행, 자동 시작의 .venv 경로를 frozen 실행 방식과 대조해야 한다. 현재 소스 실행·정상 종료 검증은 EXE 자식 실행·종료·업데이트 재진입 검증을 대체하지 않는다.
- FFmpeg/ffprobe, 템플릿·정적 이미지·SVG·폰트·migration·tzdata·필요 DLL의 패키징과 clean-PC 자원 탐색을 검증해야 한다. tzdata는 해당 venv metadata에는 없지만 기존 별도 fixture vendor와 시간대 PASS 증거가 있다. ONNX runtime의 해당 venv 미설치를 PC 전체 미설치나 실제 로컬 음성 불가능으로 확대 해석하지 않는다.
- libx264를 사용하는 현재 경로에 맞는 재배포 가능 FFmpeg 빌드와 라이선스·소스 제공·고지·빌드 옵션 확인이 필요하다. 공식 FFmpeg는 기본 LGPL이나 GPL 구성요소를 켠 빌드는 GPL 적용, enable-nonfree 빌드는 재배포 불가라고 설명한다. 별도 NewsFlow 프로그램 자체의 라이선스까지 여기서 단정하지 않는다. [FFmpeg 공식 법률·라이선스 안내](https://www.ffmpeg.org/legal.html)
- Node·Playwright는 현재 GUI 검증 도구이며 일반 제품 실행의 필수 dependency로 확인되지 않았다. 사용자 GUI는 로컬 서버와 시스템 브라우저를 사용한다. Chrome 155 검증을 Chrome 번들 의무로 해석하지 않는다.
- LocalAppData 기반 사용자별 DB·미디어와 CurrentUser DPAPI 구조는 있으나 서로 다른 표준 사용자 간 데이터·키·ledger 접근 분리는 NOT VERIFIED이다.
- loopback·CSRF·Origin·CSP는 존재하지만 다른 로컬 사용자의 신원 인증을 대신하지 않는다. 민감 GET·미디어 접근 정책, 사용자별 포트 충돌, OAuth redirect와 동시 실행 조합이 배포 전 확인 대상이다.
- 실제 설치 프로그램, 코드 서명, Python 없는 새 PC 실행, 업데이트·제거 시 데이터 보존, frozen 복원·롤백은 NOT IMPLEMENTED 또는 NOT VERIFIED이다.

Step 14 운영 적용·앱 재시작은 별도 승인이 필요하다. Step 15에서는 합성 자료만 사용하는 PyInstaller/Nuitka 최소 빌드 비교의 승인을 요청할 수 있으나 지금 도구를 선정하거나 설치파일 제작을 시작하지 않는다. Step 16~18의 다수 사용자·업데이트·제거·복구·서명 검증을 마치기 전 일반 사용자 배포는 BLOCKED이다.


7. 실제 연동과 통신 검증의 한계
실제 SerpApi·OpenAI·Claude·ElevenLabs·Higgsfield 계정/테스트키·생성 권한·잔액·청구는 미검증이다. 실제 OAuth·토큰 갱신·SNS 게시도 하지 않았다. 승인 시 공급사·모델·합성 입력·호출 수·가격 조건·결과 불명 중단 범위를 먼저 고정해야 한다. Fake 견적1.50달러나 테스트 usage는 실제 요금이 아니다.
Python·Node·페이지 요청 차단과 Fake 응답, 합성 AppData·SQLite 및 전용 브라우저 프로필을 유지했다. 현재 Windows 사용자의 운영 파일 접근 권한이나 Chrome 자체 백그라운드 통신까지 완전 격리했다는 뜻은 아니다. 기존에 수용된 이 제한을 유지하며 Sandbox/Hyper-V/계정/ACL/방화벽 변경은 0건이다.

9. 다음 작업과 승인
Step14 운영 적용·재시작은 별도 승인 대상이다. 후보 코드·보존 백업·현재 작업 상태·적용/복구 범위를 확인한 뒤 승인할 수 있으며 이번 결과로 실행하지 않는다.
Step15는 합성 자료 기반 EXE 최소 빌드 비교의 승인 검토가 가능하다. PyInstaller/Nuitka 선정, frozen 자식 실행·자산·사용자별 데이터·포트·설치/업데이트/제거를 실제로 검증해야 한다. Step16~18과 일반 배포는 미승인이다.
우선 처리 순서: 남아 있는 CI/운영 전환 위험 검토 → 필요한 모델 선택·credential 연결 최소 범위 승인 → Step15 합성 빌드 비교 승인 → 별도 실제 API 시험 및 다수 사용자 검증. 자동으로 새 개발을 시작하지 않는다.
결과 제출 후 중단하며 운영 앱 종료 상태를 유지한다.
