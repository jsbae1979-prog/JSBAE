# 새 캐릭터 작업이 이전 오류에 묶이는 UI 수정

2026-10-29. 사용자 캡처에서 새 캐릭터·주제를 선택했는데 이전 오류와 ‘작업 이력 확인 후 새 작업’ 안내 때문에 스토리 버튼을 누르지 못하는 상태를 확인했다.

## 원인과 변경

- 기존 코드는 오류 문자열이 하나라도 남으면 생성 버튼 전체를 비활성화했다. 실패 후 주제를 바꿔도 이전 요청 ID를 유지하여, 바뀐 본문을 같은 ID로 보내면 서버의 body-hash 불일치 검증에서 422가 발생할 수 있었다. 작업 이력의 존재 자체가 금지 조건인 것은 아니었다.
- 오류 전체를 이유로 버튼을 잠그는 조건을 제거했다. 주제·참조·설정·한도에 따른 명시적 새 입력은 새 요청 ID로 구분한다. 이미 결과 불명인 동일 입력은 자동 재전송하지 않는다.
- 초안 생성 전에 확정된 로컬 422 검증 오류는 유료 실행 결과 불명과 구분한다. 입력 수정 후 재입력할 수 있다. 참조 우선순위는 실제 전송 내용과 일치시켰고, 목록 갱신 실패로 busy가 계속 남는 문제도 정리했다.
- ‘작업 이력 확인 후 새 작업’을 강제하는 안내는 ‘새 스토리 입력’으로 바꿨다. 이전 작업·이미지·비용·결과 불명 이력은 삭제하지 않는다.

## 집중 검증 및 범위

실제 React 컴포넌트 함수와 disabled 조건을 Node에서 실행하고 외부 전송을 로컬 stub으로 대체한 집중 검사 8 PASS, TypeScript PASS, 최종 Vite 빌드 PASS다. 실제 Chrome에서 유료 생성 버튼을 눌러 Claude 성공을 확인한 결과가 아니다. API 권한·키 복호화·과금 한도를 추가로 확대하지 않았다.

‘자막·추가 음성 없는 FFmpeg 합성’ 수정 14 PASS와 함께 개발 브랜치에 보존했다. 개발 검증 시점에는 두 변경을 운영에 적용하지 않았으며, 이후 명시적 운영 반영 승인을 받아 아래와 같이 처리했다. 현재 사용자가 입력한 운영 화면·파일·DB·키·미디어는 이 개발 작업으로 변경하지 않았다.

## 승인 후 운영 확인

사용자의 추가 승인을 받아 제품 코드 `1b394414e6f333bb7c74471d0fe54410da969eea`의 정확한 5개 파일을 반영하고 정상 Stop·Start 1회를 수행했다. Stop 종료 코드 0, loopback 18768 정상 준비와 Chrome 새 인증을 확인했다. 기사 169건·47개 테이블 전체 건수 불변, 보호된 키·미디어 26개 및 기존 캐릭터·작업 파일 34개의 내용과 ACL 불변, 원본·백업 A/B 불변 및 정지 시점 프로필 스냅샷의 DB 일치를 확인했다.

실제 Chrome에서 기존 작업과 분리된 새 입력 화면을 열고, 사용자가 저장한 캐릭터와 캡처의 주제·Kling O3 Standard·30초(6초×5)·소리 켜기·1080p 출력을 복원했다. 작업 이력 오류 안내가 없고 ‘스토리 자동 생성하기’ 버튼이 활성화된 것을 확인했다. 생성 버튼은 누르지 않았으며, 새 공급사 요청은 0회다. 종료된 중복 NewsFlow 탭만 닫고 현재 작업 화면은 유지했다.

유료 Claude·Higgsfield 실행의 기존 외부 실행 경계와 승인 조건은 이번 변경에서 확대하지 않았다. 따라서 이 결과는 새 유료 생성 요청의 성공까지 뜻하지 않는다. 실제 생성은 별도 사용자 실행·비용 승인 범위에서 확인할 항목이다.

판정: UI 잠금 수정·운영 적용 ACCEPTED. 실제 새 유료 생성 성공 여부는 NOT VERIFIED이므로 전체 제작 흐름은 CONDITIONAL로 유지한다.
